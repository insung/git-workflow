# v0.8.0 — Issue 중심 기록과 프로젝트 브랜치 정책 통합

Issue의 계획과 PR의 실제 결과를 기본 기록으로 사용하여 불필요한 작업 파일 생성을 줄인다. workflow-init은 기존 템플릿의 갱신과 프로젝트 브랜치 정책 초기화를 제공한다.

## 기능·개선

- 사용자 요청 원문과 참고 링크를 Issue에 남기고 계획·제약·AC를 구현과 연결한다. 상세 plan은 설계·의존성 설명이 필요한 경우, task는 독립 역할 계약이 필요한 경우에만 분리한다.
- 검토·인계·원시 로그 파일을 자동 생성하지 않는다. 다시 얻기 어려운 고유 증거와 독립 검토 입력은 필요한 위치에 보존하며, 기존 작업 문서로 진행 중인 작업을 재개할 수 있다.
- workflow-init에서 프로젝트 브랜치 정책을 독립 선택한다. 기존 관행 유지·GitHub Flow·Trunk 기반·Release Flow·Gitflow·기존 dev/feature/prod/hotfix 흐름을 비교하고 승인한 단일 정본과 최소 읽기 연결을 기록한다.
- 일반 브랜치·PR 대상·hotfix 요청은 승인된 프로젝트 정책을 읽는다. 충돌·미정이 있으면 해당 행동을 보류한다. 정책 초기화는 실제 브랜치·보호 설정·배포 자동화 변경을 포함하지 않는다.

## 수정

- 기존 템플릿도 명시적인 설치·갱신 요청 또는 해당 항목 선택으로 선택한 정본 전체로 교체한다. 기존 파일명·경로를 유지하고 새 파일 준비·검증 뒤 교체한다. 읽기 전용·기존 내용 보존 요청은 별도 경로를 따른다.
- 로컬 소스를 지정한 요청은 해당 작업공간의 지침과 자산을 사용한다. 설치된 이전 캐시로 대체하지 않는다.

## 전환 안내

- branch-strategy 스킬을 제거했다. 전략 기록은 workflow-init의 브랜치 정책 항목으로 전환하고, 실제 분기는 프로젝트 정책을 읽는 일반 작업 요청으로 수행한다. 기존 dev/feature/prod/hotfix 후보는 유지한다.
- 정책 후보 선택은 문서 쓰기 승인이 아니다. 파일 경로·내용·위치 승인 후 기록하며 기존 README와 AGENTS 내용을 보존한다. 적용 직전 상태가 달라졌다면 새 상태로 다시 제안한다.
- 플러그인 갱신만으로 소비 프로젝트의 템플릿은 바뀌지 않는다. 갱신이 필요하면 workflow-init에 선택한 템플릿의 설치·갱신을 요청한다. 전체 교체 시 기존 사용자 정의 항목도 정본으로 바뀌므로 보존이 필요하면 이를 명시한다.
- 과거 docs/git-workflows는 새 기록 방식 적용만으로 삭제하지 않는다. 별도 정리 요청에서 맥락·참조·고유 증거를 대조한다. 이번 준비에서는 사용자 승인으로 이 저장소의 과거 225파일을 65파일로 정리했다. 핵심 판단·검증 결과·한계와 정리 전 고정 commit 링크를 유지한다. 소비 프로젝트의 기존 기록을 자동 삭제하는 변경은 아니다.
- 설치자는 0.8.0 발행 후 Codex와 Claude Code에서 플러그인을 갱신하고 새 세션을 시작한다. 설치된 버전·활성 상태·캐시 내용은 별도로 확인한다.

- 조사 범위: 공개 v0.7.0 `25cb8a9` → 원격 main `3993cb3`. 세 manifest를 0.8.0으로 맞춘 발행 준비 패키지다. 최종 태그 대상은 이 변경이 검토·머지된 뒤 확정한다.
- [PR #34](https://github.com/insung/git-workflow/pull/34), [PR #38](https://github.com/insung/git-workflow/pull/38), [PR #37](https://github.com/insung/git-workflow/pull/37)의 실제 변경을 포함한다.
- 최종 준비 작업본의 패키지·링크·라벨·템플릿 교체 검사 결과와 대상 커밋은 Issue #39의 연결 PR에 기록한다. 과거 검증과 최종 준비 패키지의 검증을 구별한다.
- PR #34의 독립 판정 warn과 일부 변경 전 시나리오의 실행 순서 한계를 보존한다. PR #37·#38의 응답 사례와 임시 저장소 적용 검증은 모든 호스트의 자동 탐색·실제 소비 프로젝트 적용을 증명하지 않는다.
- 브랜치 초기화의 승인·상태 재확인·정본 기록과 일반 작업의 정책 적용은 [짧은 흐름](../../skills/workflow-init/references/branch-policy.md#간략한-워크플로우)으로 확인한다.
- 태그 push·공개 Release 발행·호스트 재설치는 미실행이다. 공개 노트 확정 시 최종 검증과 실제 발행 상태를 다시 대조한다.
