# v0.13.0 — Issue·PR 제목 구분과 AI 코멘트 식별

## Issue·PR 제목 구분과 AI 코멘트 식별

Issue와 PR은 제목 앞의 표기로 구별하고, AI가 작성한 코멘트에서는 회신 유형과 작성 도구를 첫 줄에서 확인할 수 있다.

## 변경 사항

### 🚀 기능·개선

- Issue 제목은 `[Issue] <작업 목표>`, PR 제목은 `[PR] <실제 변경 내용>`으로 쓴다. 제목에서 type·scope를 제거하고 분류는 라벨로 관리한다. 커밋 제목의 `type(scope)` 형식은 유지하며 Squash 최종 제목은 커밋 규칙으로 변환한다.
- AI 댓글·리뷰·스레드 답글의 첫 줄에 회신 유형과 실제 작성 AI를 강조한다. 긴 답글은 결과·직접 근거·남은 판단을 구별하며 부분 반영 이유와 검증 한계를 유지한다.

### 🐛 수정

- 회신 검증기는 준비 본문과 저장 본문이 같더라도 필수 AI 표기 첫 줄이 없으면 완료로 인정하지 않는다. 자리표시자·허용되지 않은 유형·인용 또는 코드 예제 속 표기도 거절한다.

## 업그레이드 안내

- Claude Code·Codex 플러그인을 0.13.0으로 갱신하고 새 세션을 시작한다.
- 새 표기는 신규 기록에 적용한다. 과거 제목·인간 댓글·기존 AI 댓글을 소급 수정하지 않는다. 소비 프로젝트의 템플릿은 workflow-init으로 갱신을 요청할 때 바뀐다. 명시적인 소비 프로젝트 제목 규칙은 우선한다.
- 회신 검증기를 직접 사용하는 호출자는 새 첫 줄을 포함한 본문을 준비해야 한다. 기존 하단 서명만 있는 본문은 새 검증 기준을 충족하지 않는다. GitHub의 실제 작성자 계정은 바뀌지 않는다.

## 검증

Node 회귀 검사와 패키지·링크 검사를 수행했다. 공개 모의 요청을 별도 실행자에게 기존·변경 지침으로 각각 실행해 제목과 코멘트 출력, 인간 댓글 보존·중복 방지·게시 후 누락 처리를 대조했다. 이 결과는 실제 두 호스트의 자동 스킬 선택이나 모든 미래 실행의 준수를 증명하지 않는다.
