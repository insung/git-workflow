# v0.14.0 — 작업 단위 축소와 이슈 종료 기록 정합성

## 작업 단위 축소와 이슈 종료 기록 정합성

같은 결과의 보완을 한 작업으로 묶고 불필요한 이슈·후속 보고를 줄인다. PR은 Refs로 연결하며, 이슈는 최종 본문과 결과 댓글을 확인한 뒤 별도로 종료한다.

## 변경 사항

### 🚀 기능·개선

- 독립 추적이 불필요한 경미한 정합성 보완은 조건을 충족하면 새 Issue 없이 PR로 전달한다. 실제 관련 Issue가 있으면 재사용하고, API·데이터 계약·보안/권한·배포 등의 변경에는 이 예외를 적용하지 않는다.
- 기존 계획에 포함된 항목과 영향이 낮은 선택적 개선을 새 후속 과제로 자동 등록하거나 반복 보고하지 않는다. 현재 목표를 막는 위험과 필수 미완료는 계속 명확히 보고한다.
- workflow-init은 공통 작업 단위·Issue 예외·후속 보고 기준을 읽는 한 줄을 제안한다. 같은 의미의 선언은 중복 추가하지 않고, 기존 강제 규칙과 충돌하면 승인 전 추가·교체를 보류한다.
- 실제 해결·부모·의존 관계와 결정의 직접 출처는 정상 참조를 유지하며, 단순 배경 링크에만 역참조 없는 연결을 사용할 수 있다.

### 🐛 수정

- PR의 기본 Issue 연결을 `Refs:`로 바꾸고, 머지 시 자동 종료는 사용자가 명시적으로 요청한 경우만 허용한다. 본문·커밋·최종 메시지·수동 연결의 자동 종료 경로도 확인한다.
- 종료 전에 「한눈에」·계획·AC·남은 조치를 실제 근거에 맞춰 저장·재조회하고 결과 댓글을 확인한다. 저장 실패·불일치면 종료를 멈추며, 이미 닫힌 Issue도 낡은 상태를 보완한다.

## 업그레이드 안내

- Claude Code·Codex 플러그인을 0.14.0으로 갱신하고 새 세션에서 사용한다.
- 기존 저장소 AGENTS·템플릿·GitHub 보호 설정은 자동으로 변경하지 않는다. workflow-init 적용 시 누락된 안내만 제안하며, 저장소의 명시적 Issue 필수 정책과 승인 경계는 우회하지 않는다.
- 과거 Issue·PR·역참조를 일괄 수정하지 않는다. Issue 생략은 요청 근거·검증·머지 승인 생략을 뜻하지 않는다.

## 검증

Node 107건·Python 30건과 패키지 구조·링크·diff 검사를 통과했다. Refs·종료 절차 및 작업 단위·보고·init의 공개 가상 사례를 변경 전후 대조했다. 실제 호스트 자동 선택/로딩·원격 경쟁·반복 안정성·시간/비용 효과는 이 결과로 보증하지 않는다.
