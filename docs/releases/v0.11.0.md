# v0.11.0 — 단계가 보이는 Issue 본문과 줄 단위 PR 검토

공개 Release name: `v0.11.0`

## 단계가 보이는 Issue 본문과 줄 단위 PR 검토

Issue 본문 맨 위의 「한눈에」와 단계 표로 지금 단계와 다음 행동을 바로 알 수 있다. `pr-review`는 요청하면 검토 결과를 PR 파일의 줄 코멘트로 게시하고, 배포 뒤 확인이 남은 Issue는 확인을 마칠 때까지 completed로 닫지 않는다.

## 변경 사항

### 🚀 기능·개선

- **Issue 본문 양식:** 맨 위 「한눈에」에 지금 단계, 다음 행동과 수행 주체, 막힌 것을 둔다. 계획은 단계 표 하나로 쓰고 상태 열을 상태의 정본으로 한다. 진행 중 본문은 단계 상태·사실·결정이 바뀔 때만 고치고, 결정은 「결정 기록」에 결정 ID·질문·답으로 남긴다. 사용자 요청 원문은 맨 아래에 접어 둔다. AC 체크박스는 `issue-close`가 닫을 때 근거와 함께 체크한다. [#75](https://github.com/insung/git-workflow/pull/75)
- **줄 코멘트 PR 검토:** 줄 코멘트 게시를 요청하면 `pr-review`가 검토 HEAD에 Review 하나를 게시한다. 본문에 AC 요약과 줄 없는 지적을, diff 안의 fail·warn·human-review 지적에 줄 코멘트를 붙인다. 승인·변경 요청 이벤트는 쓰지 않는다. 게시 뒤 다시 조회해 일치할 때만 완료로 보고한다. 요청이 없으면 기존처럼 대화나 일반 댓글로 반환한다. [#77](https://github.com/insung/git-workflow/pull/77)
- **배포 뒤 확인 항목:** 배포 뒤에야 확인할 수 있는 항목을 Issue 계획의 「전달」에 시점·대상·확인 방법·판정 기준으로 정의한다. PR은 해당 AC를 「충족(배포 뒤 확인 대기)」로 보고하고 `Closes` 대신 `Refs`를 쓴다. `issue-close`는 미확인 항목이 있으면 completed로 닫지 않는다. 배포 뒤 확인이 없는 작업은 지금과 같다. [#71](https://github.com/insung/git-workflow/pull/71)

### 🐛 수정

- **깨진 참조 정리:** 「기록 커밋」 링크 세 곳이 `pr-review`의 「7. 검토 기록 보존」 절로 이동한다. PR 검토 댓글의 「진행 요약」·「근거 문서」·「남은 일」 구조를 `pr-comment.md`에 직접 정의한다. 패키지 검사가 로컬 Markdown 링크의 앵커도 검사한다. [#79](https://github.com/insung/git-workflow/pull/79)

## 업그레이드 안내

- Claude Code와 Codex에서 플러그인을 0.11.0으로 갱신한 뒤 새 세션을 시작한다.
- 새 Issue 양식은 새로 만들거나 다시 쓰는 Issue에 적용된다. 기존 Issue 본문과 소비 프로젝트의 Issue 템플릿은 자동으로 바뀌지 않는다. 템플릿은 `workflow-init`으로 갱신을 요청할 때 바뀐다.
- 줄 코멘트 Review는 요청할 때만 게시한다.

## 검증

각 PR에서 패키지 회귀 검사와 변경 전후 행동 사례를 대조했다. 이번 준비에서 `node --test tests/*.test.mjs`와 `node scripts/check-package.mjs`(앵커 검사 포함)를 다시 실행했다. 실제 호스트의 자동 호출 선택과 GitHub 웹의 링크 동작은 PR별 기록의 범위를 따른다. 자세한 AC·명령·결과는 위 PR에 있다.
