# v0.15.0 — 목표 단위 진행 순서도와 변경 보고

## 목표 단위 진행 순서도와 변경 보고

목표 하나에 여러 Issue·저장소·하위 세션이 관련될 때 쓰는 issue-flow 스킬을 추가한다. 목표의 Issue·PR·하위 세션 작업을 순서도로 그리고, 이전 보고와 비교해 진행 위치와 변경을 알린다.

## 변경 사항

### 🚀 기능·개선

- issue-flow는 목표 하나의 Issue·PR·하위 세션 작업을 순서도로 그린다. 순서도에는 목표 문장, 노드마다 핵심 설명, Issue·PR 번호를 넣고, 모양은 정하지 않는다. 결정 ID·AC 번호 같은 내부 ID와 상태 영문 값은 보고에 쓰지 않는다.
- Issue 번호로 요청하면 그 Issue의 목표를 목표로 삼는다. 목표를 가진 Issue는 목표와 함께 쓰고, 그 목표를 이루는 sub-issue·PR·하위 세션 작업을 노드로 그린다. 목표를 정할 근거가 없으면 「정하는 중」으로 쓰고 묻는다.
- 보고마다 `flow-<목표 슬러그>.json`에 노드 상태 버전을 더하고 순서도 원본을 `-v<n>` 파일로 남긴다. 순서도 파일은 그 파일만 열어도 같은 모양으로 보이게 저장한다. 다음 보고는 두 파일을 읽어 완료·추가·수정·제외를 나눈다.
- 노드 상태는 완료·진행 중·사용자 대기·시작 전·제안·제외 여섯 가지다. 완료는 원본 데이터를 다시 확인한 것만 쓴다(Issue·PR은 GitHub 재조회, 결정은 사용자 답, 번호 없는 작업은 결과 파일·커밋).
- 검토를 요청받으면 하위 세션의 결과를 Issue의 계획·달성 조건과 대조해 「보완할 것」을 쓰고, 새로 찾은 작업은 제안 노드로 더한다.
- 보고는 요약, 순서도, 변경표를 기본으로 하고, 보완할 것과 사용자가 할 일을 해당할 때 더한다. 요청이 원하는 설명이나 형식도 더할 수 있다.
- 한 세션 안의 단계 표 질문은 progress-report가 맡는다. 하위 세션이나 여러 Issue가 관련된 남은 작업 질문은 issue-flow가 맡는다.

## 업그레이드 안내

- Claude Code·Codex 플러그인을 0.15.0으로 갱신하고 새 세션에서 사용한다.
- 기존 스킬의 동작은 바뀌지 않는다. 기본 흐름은 채팅 하나가 변경 하나를 조율하며, issue-flow는 목표 하나에 여러 Issue·저장소·세션이 관련될 때만 쓴다.
- 기록 파일(json·순서도)은 대상 저장소에 커밋하지 않는다.

## 검증

Node 107건·Python 30건과 패키지 구조·링크·플러그인 매니페스트·diff 검사를 통과했다. 패키지 검사의 필수 스킬 목록에 issue-flow를 더했다. 실제 호스트의 자동 선택·로딩, progress-report와의 발동 구분, 순서도 렌더링은 이 결과로 보증하지 않는다.
