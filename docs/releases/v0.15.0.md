# v0.15.0 — 목표 재검토 순서도 스킬과 Issue 생성 승인 정의

## 목표 재검토 순서도 스킬과 Issue 생성 승인 정의

관리 세션이 하위 세션 보고를 원본 데이터로 재확인하고 목표 달성 여부를 순서도로 보고하는 goal-flowchart 스킬을 더한다. 조건부·다른 세션 지시만으로는 Issue를 만들지 않고 판정과 초안을 먼저 보고하며, 스킬·안내 문서의 모호한 일상어를 한 가지 뜻의 용어로 바꾼다.

## 변경 사항

### 🚀 기능·개선

- `git-workflow:goal-flowchart`로 관리 세션이 하위 세션 보고를 GitHub·파일·커밋으로 재확인하고, 목표 달성 판정(달성·달성 가능·조건부·현재 범위로는 불가)과 한 작업·남은 작업의 순서도, 차단 요인, 권장 순서를 보고한다. 목표 하나에 여러 Issue·저장소·세션이 관련될 때 쓰며, Issue가 없는 작업도 번호 없는 상자로 그리고 Issue 생성을 요구하지 않는다. 보고는 읽기 전용이다. [PR #101](https://github.com/insung/git-workflow/pull/101)
- 「없으면 Issue 하나」 같은 조건부 지시나 다른 세션이 보낸 지시를 받으면 Issue를 만들기 전에 Issue 필요 판정과 초안을 보고하고 사용자 승인을 받는다. 판정은 변경 유형별로 Issue 「영향 범위」 또는 PR `## 요청 근거와 해결 범위`에 같은 형식으로 기록한다. [PR #96](https://github.com/insung/git-workflow/pull/96)
- 공개 저장소의 Issue·PR·댓글에는 비공개 저장소·테이블·로컬 경로 같은 식별자를 가상 이름·역할 이름으로 바꿔 쓰고, 바꾼 종류를 한 줄로 밝힌다. [PR #96](https://github.com/insung/git-workflow/pull/96)

### 📚 운영·기록 개선

- 스킬·안내 문서에서 여러 동작으로 읽히는 일상어를 문맥에 맞는 한 가지 용어로 바꿨다. Issue 템플릿의 「막힌 것」은 「차단 요인」, 브랜치 흐름의 「반영·역반영」은 「머지·역머지」로 바뀐다. [PR #100](https://github.com/insung/git-workflow/pull/100)

## 업그레이드 안내

- Claude Code·Codex 플러그인을 0.15.0으로 갱신하고 새 세션에서 사용한다.
- goal-flowchart를 개인 스킬로 따로 설치했다면 플러그인 갱신 뒤 개인 스킬을 지운다. 둘 다 있으면 같은 발동 문구의 스킬이 두 개 보인다.
- workflow-init으로 설치한 Issue 템플릿과 AGENTS.md 선언 사본은 자동으로 바뀌지 않는다. 이미 만든 Issue 본문의 「막힌 것」도 그대로 남으며, goal-flowchart와 Issue 템플릿 대조는 두 이름을 모두 읽는다.

## 검증

Node 108건·Python 테스트 4파일과 패키지 구조·링크 검사를 통과했다. goal-flowchart는 Issue 없는 작업 사례 1건을, Issue 생성 승인은 공개 가상 사례 5건을 하위 에이전트로 실행해 확인했다. Issue 생성 승인의 생성 여부 개선(PR #96 AC-04)은 변경 전에도 Issue를 만들지 않아 부분 충족이다. 실제 호스트 자동 선택·로딩과 반복 안정성은 이 결과로 보증하지 않는다.
