# v0.15.0 — 목표 단위 진행 순서도와 변경 보고

## 목표 단위 진행 순서도와 변경 보고

목표 하나가 여러 Issue·저장소·하위 세션에 걸칠 때 쓰는 issue-flow 스킬을 추가한다. 목표의 Issue·PR·결정을 순서도로 그리고, 지난 보고와 비교해 진행 위치와 변경을 알린다.

## 변경 사항

### 🚀 기능·개선

- issue-flow는 목표 하나의 Issue·PR·사용자 결정을 순서도로 그린다. 순서도에는 목표 문장, 노드마다 무슨 일인지 한 줄, Issue·PR 번호를 넣고, 모양은 정하지 않는다. 결정 ID·AC 번호 같은 내부 ID만으로 노드를 부르지 않는다.
- Issue 번호로 요청하면 그 Issue의 목표를 목표로 삼아 연결된 sub-issue·PR·결정 기록의 흐름을 그린다.
- 보고마다 `flow-<목표 슬러그>.json`에 노드 상태 판을 더하고 순서도 원본을 `-v<n>` 파일로 남긴다. 다음 보고는 두 파일을 읽어 완료·새로·바뀜·삭제를 나눈다.
- 노드 상태는 done·now·wait_user·todo·dropped 다섯 가지다. done은 GitHub를 다시 조회해 PR MERGED·Issue CLOSED를 확인한 것만 쓴다.
- 보고는 첫 줄 요약(`v3 → v4: 완료 2 · 새로 1 · 바뀜 1 · 삭제 0`), 순서도, 변경표, 사용자가 할 일, 대기 중 결정 순서로만 쓴다.
- 한 세션 안의 진행 상황·남은 일 질문은 progress-report가 맡도록 발동 문구를 나눈다.

## 업그레이드 안내

- Claude Code·Codex 플러그인을 0.15.0으로 갱신하고 새 세션에서 사용한다.
- 기존 스킬의 동작은 바뀌지 않는다. 기본 흐름은 채팅 하나가 변경 하나를 조율하며, issue-flow는 목표 하나가 여러 Issue·저장소·세션에 걸칠 때만 쓴다.
- 기록 파일(json·순서도)은 대상 저장소에 커밋하지 않는다.

## 검증

Node 107건·Python 30건과 패키지 구조·링크·플러그인 매니페스트·diff 검사를 통과했다. 패키지 검사의 필수 스킬 목록에 issue-flow를 더했다. 실제 호스트의 자동 선택·로딩, progress-report와의 발동 구분, 순서도 렌더링은 이 결과로 보증하지 않는다.
