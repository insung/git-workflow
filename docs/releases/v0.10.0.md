# v0.10.0 — 코드 의도·변경 영향 조사와 머지 후 정리 개선

공개 Release name: `v0.10.0`

## 코드 의도·변경 영향 조사와 머지 후 정리 개선

“왜 이렇게 구현했는지 알려줘”, “이걸 바꾸면 어디에 영향이 있어?” 같은 요청을 `git-history`로 조사한다. `pr-merge`는 머지 직후 원격 head를 정리하고, `git-release`는 마일스톤 종료 승인을 발행 승인과 함께 묻는다.

## 변경 사항

### 🚀 기능·개선

- **코드 의도·변경 영향 조사:** `git-history`가 명시 요청의 구현 의도·도입 이유를 설명한다. 변경 영향 요청에는 현재 호출·설정·테스트와 유지할 계약·검증안을 보고한다. 조사만 요청하면 보고로 끝나며, 일반 구현에 자동 조사나 재승인 단계를 추가하지 않는다. [사용 설명](https://github.com/insung/git-workflow/blob/main/docs/guides/code-context-investigation.md)과 예시 5개를 제공한다. [#61](https://github.com/insung/git-workflow/pull/61)
- **구현 절차 간소화:** 공개 AC·계획으로 충분한 작업은 별도 검토 입력 없이 진행한다. 스킬 변경은 행동 주장별 사례·판정 근거로 검증하고 결과 요약을 PR에 재사용한다. 역할 분리·승인·비공개 입력 경계는 유지한다. [#63](https://github.com/insung/git-workflow/pull/63)

### 🐛 수정

- **머지 후 원격 head 정리:** `pr-merge`가 실제 머지를 확인한 뒤 안전 조건을 충족한 원격 head를 별도 질문 없이 삭제하고 사후 조회한다. Issue 종료 여부와 관계없다. `issue-close`는 원격 head를 삭제하지 않고 남은 head를 조회해 보고만 한다. 로컬 브랜치 삭제는 지금처럼 별도 승인 대상이다. [#67](https://github.com/insung/git-workflow/pull/67)
- **마일스톤 종료 승인:** `git-release`의 발행 승인 요청에서 대상 마일스톤의 이름·번호·완료율과 종료 여부를 별도 항목으로 함께 묻는다. 종료 승인이 없으면 닫지 않고 「마일스톤 종료 승인 대기」를 보고한다. 발행 승인만으로 닫지 않는 규칙은 유지한다. [#66](https://github.com/insung/git-workflow/pull/66)

### 📚 운영·기록 개선

- **공개 릴리즈 노트 형식:** Release name은 버전만, 본문 첫 H2는 핵심 변화로 쓴다. 분류별 짧은 변경 목록·업그레이드 안내·검증·전체 비교 링크를 기본 구성으로 하고 승인·보존·호환성·검증 한계는 유지한다. [#59](https://github.com/insung/git-workflow/pull/59)

## 업그레이드 안내

- Claude Code와 Codex에서 플러그인을 0.10.0으로 갱신한 뒤 새 세션을 시작한다.
- `pr-merge`의 머지 승인에 원격 head 삭제가 포함된다. 다른 열린 PR이 같은 head를 쓰면 삭제를 보류한다. `gh pr merge --delete-branch`는 계속 쓰지 않는다.
- `workflow-init`의 AGENTS 선언에 조사 호출 안내가 추가된다. 기존 프로젝트의 AGENTS.md는 자동으로 바뀌지 않으며, 다시 요청하면 누락 문단만 제안한다.

## 검증

각 PR에서 패키지 회귀 검사와 변경 전후 행동 사례를 대조했다. 실제 호스트의 자동 호출 선택·효과 측정과 독립 PR 리뷰는 PR별 기록의 범위를 따른다. 자세한 AC·명령·결과는 위 PR에 있다.
