# feat(issue-review): Issue에서 Wiki까지 단계별 Git 워크플로우

상태: local-draft. GitHub 인증 실패로 원격 Issue를 생성하지 않았다. 번호와 URL은 없다.

## 변경 의도

하나의 큰 스킬을 필요한 단계만 호출할 수 있는 플러그인으로 나눈다. 요청의 의도와 영향 범위를 Issue에서 확정하고 구현 문서, spec-it 검토, 사용자 승인, 실제 머지, Wiki 기록을 연결한다.

## 영향 범위

- 포함: git-workflow의 스킬·템플릿·사용 안내·패키지 검사
- 제외: spec-it 정책 및 runner 수정, EC2/Actions 구축, 설치 캐시 변경, 원격 Issue/PR 생성, 머지와 Wiki 발행
- 호환성: 기존 git-workflow 진입 이름과 커밋·브랜치·릴리즈 기능 유지

## 달성 조건

아래 완료 표시는 로컬 스킬 계약과 시험 안내 구현에 대한 것이다. 실제 GitHub 실행이나 모델의 판정 정확도는 [검증 결과](verification.md)의 미확인 범위로 남긴다.

- [x] Issue·구현/PR·검증·머지/Wiki를 개별 스킬로 호출
- [x] 의도·영향 범위·완료 기준 없는 Issue에서 구현 차단
- [x] 구현 판단과 검증 인계 기록을 대상 리포 docs/에 보존
- [x] diff와 원래 의도를 대상의 pinned spec-it 기준·테스트 증거에 대조
- [x] 검증 뒤 사용자 승인과 실제 머지 확인을 거쳐 Wiki 작성·게시
- [x] 로컬 파일 호출 예시와 검사 명령으로 미발행 후보 시험 가능

## 검증 계획

패키지 무결성 검사, 검사기 단위 테스트, Claude 플러그인 구조 검사, 기존 스킬 대비 압박 사례 및 새 스킬의 별도 에이전트 시나리오 검토를 수행한다. 실제 원격 쓰기와 클라우드 자동화를 증명하지 않는다.
