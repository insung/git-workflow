# 운영 릴리즈 / Production release

> dev의 통합 변경을 운영에 반영하고 릴리즈 노트를 준비해줘.

## 흐름

릴리즈 범위·관련 Issue 확인 → 필요 시 릴리즈 Issue/plan → dev에서 prod 대상 PR → 통합/회귀·배포/롤백 근거 → pr-review·사용자 승인·pr-merge → 실제 승인된 배포와 사후 확인 → git-release: 이전 릴리즈..선택한 prod 커밋 비교·노트·승인된 발행

## 확인할 경계

- 배포와 태그의 정확한 실행 순서는 실제 프로젝트의 트리거와 정책을 따른다.
- 필수 Issue 연결에는 실제 승인된 릴리즈 범위와 달성 조건이 대응해야 한다.
- GitHub Release·태그만으로 서버 배포를 완료했다고 하지 않는다.
- 배포 실패·복구·태그/Release 발행 상태는 각각 사실에 맞게 기록한다.
