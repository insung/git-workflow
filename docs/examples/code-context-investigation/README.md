# 코드 의도·변경 영향 조사 사용 예시

의도를 설명받는 질문과 변경 영향을 묻는 질문은 서로 다른 결과로 끝난다. 이 문서는 대표 요청과 보고 예시이며 명령·실행 경계는 [git-history](../../../skills/git-history/SKILL.md)가 정본이다. 전체 흐름은 [사용 설명](../../guides/code-context-investigation.md)에 있다.

아래 내용은 합성 사례다. 실제 저장소의 조사 결과·승인·테스트 통과를 뜻하지 않는다. 1·2번의 Git 사례는 [기존 fixture](../../../tests/fixtures/git-history/create_fixture.py)로 재현할 수 있으며 새 기능의 행동 검증 결과를 대신하지 않는다.

## 1. 포맷·이동 뒤에도 구현 이유 찾기

요청:

> format revision의 retry.py를 왜 이렇게 구현했는지 알려줘. 손님과 회원 재시도가 다른 이유를 알고 싶어.

보고 예시:

> 손님 1회·회원 3회 구분은 부하 급증을 막으려는 요청으로 도입됐다. 최근 포맷·조건문 전개·파일 이동을 거슬러 policy.py의 도입 diff와 Refs #11, PR #21, Issue #11의 요청을 연결했다. 마지막 포맷 커밋은 이 구분의 도입 이유가 아니다. PR의 테스트 통과는 당시 보고이며 이번에 직접 실행한 결과는 없다. 질문의 이유를 확인했으므로 추가 운영 측정을 요구하지 않고 종료한다.

손님 제한의 이유와 마지막 줄 변경의 이유가 다를 수 있음을 보여주는 예다. 의도 설명을 요청했으므로 코드 수정·새 Issue 작성으로 이어지지 않는다.

## 2. 최초 의도와 후속 요청 구별

요청:

> later revision에서 이 함수의 맥락을 알고싶어. 왜 손님은 이제 두 번 재시도해?

보고 예시:

> 최초 Issue #11은 손님 1회·회원 3회를 요청했다. 후속 Issue #15와 PR #25가 장애 회복 뒤 손님을 2회로 늘리고 회원 3회는 유지했다. later의 코드는 2/3이며 작업본의 미커밋 99와 구별된다. 최초 요청을 현재 2회의 이유로 소급하지 않는다.

직접 Refs가 없을 때도 PR 연결이나 저장소 문서에서 계속 찾을 수 있다. 끝내 필요한 원문에 접근할 수 없다면 동작 확인과 이유 미확인을 구별하여 보고한다. 전체 이력·모든 링크를 기본으로 요구하지 않는다.

## 3. 제안된 변경의 현재 영향

다음 호출·설정·테스트는 설명을 위한 가상 현재 코드다. 기존 fixture의 실제 파일이라고 주장하지 않는다.

| 현재 자료 | 확인할 계약 |
| --- | --- |
| api.py가 손님 요청에 retry_budget(True) 호출 | 손님 경로의 재시도 제한 |
| 설정에서 손님 분기 활성화 | 설정에 따라 달라지는 호출 경로 |
| test_retry.py가 손님 2회·회원 3회 주장 | 정상·분기 회귀 조건 |

요청:

> 손님 분기를 없애서 모두 세 번 재시도하게 바꾸면 어떤 영향이 있어?

보고 예시:

> 손님 요청의 반환값이 2에서 3으로 바뀌어 api.py의 손님 경로와 test_retry.py의 기대값에 영향이 예상된다. 회원 3회 계약은 유지된다. 설정으로 손님 분기를 사용하는 경로와 최초 부하 제한·후속 회복 요청을 함께 대조해야 한다. 손님·회원 경로와 설정 활성/비활성 검증을 제안한다. 이는 정적 예상이며 테스트를 실행하지 않았다. 수정 승인이 없는 질문이므로 영향 보고로 종료한다.

같은 대상·범위의 구현이 이미 승인된 대화라면 그 승인으로 기존 구현 절차에 인계한다. 새 중요한 영향이나 계획 이탈이 발견됐을 때만 해당 결정을 확인한다.

## 4. 일반 구현은 기존 경로 사용

> Issue #12의 승인된 계획대로 구현해줘.

이 요청은 기존 구현 절차로 진행한다. 모든 수정마다 git-history 조사와 같은 승인 재요청을 추가하지 않는다. 구현 중 사용자가 “이 조건을 도입한 이유도 조사해줘”라고 요청하면 그 조사 범위만 연결한다.

## 5. 기존 AGENTS에 짧은 안내 추가

> 이 프로젝트 AGENTS.md에 git-workflow 조사 안내를 제안해줘.

workflow-init은 기존 선언과 동일 의미 조사 안내를 읽고 누락된 짧은 안내만 경로·전문·위치와 함께 제안한다. 기존 선언 전체를 반복하거나 상세 명령을 복사하지 않는다. 제안의 승인 전에는 파일을 쓰지 않으며 실제 절차는 [AGENTS 초기화 정본](../../../skills/workflow-init/references/agents.md)에 있다.
