# 파이썬 버전 업그레이드 계획

설명용 가상 계획이다. [Issue 초안](issue.md)의 목표 버전과 실행 경로가 미확정이며, 원격 Issue·코드 변경·검증·승인은 아직 없다. 실제 환경의 값을 조사해 대체한다.

## 맥락과 사용자 의도

사용자는 dmp.crawler의 Python 버전을 올리되 기존 수집 기능을 유지하려 한다. 현재 버전과 변경 이유를 조사하고 사용자의 목표 버전을 확정한다. 단순 선언 변경으로 끝내지 않고 의존성·실제 실행 환경·동작 회귀까지 연결한다.

## 현재 동작과 영향 범위

현재 런타임·설치 방법·컨테이너/CI·수집 진입점·산출물은 미확인이다. 조사 결과 실제 관련 파일만 수정한다. 운영 데이터 변경과 무관한 리팩터링은 제외한다. 프로젝트의 고정 spec-it 정책 채택 여부·소스를 확인하며 새로운 규칙을 임의 채택하지 않는다.

## 실행 흐름

사전 조사 → 실제 Issue 확정 → 이 계획 보완 → 01 호환성 조사 → 목표/필수 결정 확정 → dev 기반 feature 분기 → 02 구현·unit/호환성 검증 → 03 통합/배포 준비 검증 → 범위 커밋·PR 인계 → 독립 리뷰 → 사용자 승인 머지. 실패한 단위는 수정·재검증하며 새 HEAD는 다시 리뷰한다.

## 01 실행 환경과 목표 버전 호환성 조사

현재 실행 경로·Python/의존성 선언·테스트·배포 트리거를 확인한다. 목표 버전과 업그레이드 이유를 결정하고 호환성 변경 후보·파일 목록을 기록한다. 미결정이면 02의 영향받는 구현을 보류한다. [01-todos](01-todos.md).

## 02 런타임·의존성과 호환 코드 변경

branch-strategy로 실제 dev에서 feature/python-version-upgrade를 만든다. 확인한 런타임 선언·CI·이미지를 정렬하고 의존성 설치/import 및 관련 변경 코드의 unit test를 작성한다. 정상·실패·경계 입력의 기대 결과를 먼저 정의한다. [02-todos](02-todos.md).

## 03 통합·배포 준비와 PR 인계

운영 데이터나 유료 API에 쓰지 않는 fixture 기반 통합/회귀 테스트를 수행한다. 실제 배포·롤백 절차를 조사하고 승인 없는 배포는 보류한다. commit-rule로 요청한 범위만 커밋하고 handoff와 PR을 준비한다. 별도 리뷰 세션이 pr-review를 적용한다. [03-todos](03-todos.md).

## 검증 계획

| TC / AC | 사례 | 기대 결과 | 실행 방법 | 실제 결과 |
| --- | --- | --- | --- | --- |
| TC-01 / AC-01 | 목표 Python으로 실제 진입점 실행 | 런타임 일치·정상 시작 | 대상 프로젝트에서 확인한 로컬/이미지 명령 | not-run |
| TC-02 / AC-02 | 격리 환경 의존성 설치·import | 해결된 의존성 설치·주요 모듈 import 성공 | 확인한 설치/import 명령 | not-run |
| TC-03 / AC-03 | 정상 수집 fixture | 기준 결과와 동일한 필수 필드·타입·건수 | 확인한 unit/integration 명령 | not-run |
| TC-04 / AC-03 | 실패 응답·빈 응답·경계 입력 | 기존 오류/산출물 계약 유지 | mock/fixture 기반 회귀 검증 | not-run |

명령·환경·시각·대상 커밋과 사례별 기대/실제는 handoff에 기록한다. 현재 명령은 미확정이다. 구현 담당은 단위와 통합 검증을 수행하고 리뷰 담당은 실제 파일·assertion·결과를 현재 HEAD에 대조한다.

## 배포·전달과 롤백 계획

- feature → dev는 개발 통합이다. 운영 반영은 별도 릴리즈 범위에서 dev → prod PR·리뷰·승인을 거친다.
- 환경·배포 진입점·자동 트리거는 미확인이다. prod 머지가 자동 배포를 유발하는지 먼저 확인한다.
- 배포 전: 이미지/패키지 재현, 테스트 결과, 설정 호환성과 되돌릴 기존 배포 버전/이미지를 확인한다.
- 배포 후: 실제 시작·대표 수집·오류·산출물 계약을 확인할 담당·관찰 구간·중단 기준을 정한다.
- 롤백: 시작 실패나 계약 위반 시 확인한 이전 런타임/이미지로 복구하고 결과를 검증한다. 절차·권한 미확정이면 배포하지 않는다.
- 태그/Release는 선택한 prod 커밋 기준이며 실제 배포 완료와 별도다. Wiki 작성은 포함하지 않는다.

## 결정·다음 행동

목표 버전, 실제 실행/배포 경로, 검증 명령·fixture, 리뷰 대상 정책 소스가 미확정이다. 먼저 01 조사와 사용자 결정이 필요하다. 이 예제의 완료 체크와 결과는 실제 작업 후에만 갱신한다.
