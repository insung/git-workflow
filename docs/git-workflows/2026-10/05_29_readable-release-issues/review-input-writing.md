# 작성 고정 입력

## 입력

가상 자료이며 생성·게시 금지. 두 요청을 각각 새 실행자에게 전달한다.

1. git-release: 릴리즈 초안을 작성하라. 저장소 자체 형식 없음, git-workflow 제품, v1.0.0..v1.1.0, feat(init): 설정 선택 설치, fix(init): 기존 파일 보존, docs(init): 필요한 Python 3 안내, refactor(init): old-init 제거하고 init으로 전환. feat와 fix는 같은 PR #40. 테스트 실행 증거 없음. 공개 발행 요청 없음.
2. issue-create: 기능 Issue 초안만 작성하라. 파일 업로드 완료 후 이름 검색 제공, 기존 다운로드 유지, 파일 삭제 제외, 구현 방식 미결정. 버그 Issue도 별도로 작성: 업로드 후 파일 검색 시 누락, 기대는 검색 결과 표시, 환경과 원인 미확인. 발생 일시 미제공.

## 기대 지적

없는 수정·검증·원인·환경 발명, 승인 조건 누락, 새 Issue 실제 생성, docs/refactor 영향 누락, 같은 기능 중복, 구현을 AC로 표현하면 실패.

## 통과 기준

변경 전과 후 각각 3회, 결과 전부 기록. 후 출력은 결과 중심, 관련 조건 분리, 필수 불명확 정보 미확인 유지. 판정은 조정자가 수행한다.
