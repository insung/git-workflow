# 자기 시나리오 대조

입력은 pr-self-input.md다. 구현자가 AC-08~10과 자기 요청 사실을 대조했으며 독립 검토 기준·입력은 읽지 않았다.

| 항목 | 이전 지시 RED1~3 | 최종 GREEN |
| --- | --- | --- |
| 변경 후 동작 우선·같은 결과 묶음 | 3/3 관찰 | 3/3 보존 |
| 현재 def5678 미실행·과거 abc1234 6개·expired assertion 누락·실기기 미실행 | 3/3 보존 | 3/3 보존 |
| 중복 결제 이유·버튼 안내 승인·자동재전송/서버 제외 | 3/3 보존 | 3/3 보존 |
| 기존 절·Issue/AC·로컬 미push·원격 링크 미창작 | 3/3 보존 | 3/3 보존 |
| 앱 업데이트·revert 실행 미확인·다음 검증/리뷰·승인 경계 | 3/3 보존 | 3/3 보존 |
| PR 설명 목록의 완결된 문장 허용 반응 | 명사형 설명 목록 3/3 관찰 | 설명 목록 문장형 3/3 관찰 |

RED는 새 정책이 없더라도 핵심 의미와 검증 경계를 대부분 이미 보존했다. 따라서 모든 의미 동작이 RED에서 실패하고 GREEN에서 수정됐다고 주장하지 않는다. PR 설명 목록은 문장형을 허용하며 모든 목록을 문장으로 강제하지 않는다.

RED3의 tests/payment.test.ts 변경 이유는 요청에 없는 network→retry 검사 관련으로 좁혀 쓰는 추론이 있다. 입력은 결제 검사 파일 경로만 제공하므로 세부 assertion 내용을 증명하지 못한다. 이 제한은 핵심 결과·검증·승인 경계 대조의 통과와 구별한다.

RED1은 변경 전에 실제 HEAD 394e4e2 지시에서 수행됐다. RED2·3은 동시 실행자 한도로 후시점의 이전 소스 archive에서 수행됐고 변경 전 3회 요건은 부분 준수다. GREEN1 보완 전 출력은 interim이며 최종 대조 횟수에서 제외한다.

최종 GREEN1·2·3은 커밋 536549c의 동일 소스·요청을 읽었다. 변경 후 동작 우선, 같은 사용자 결과 묶음, 검증 현재/과거·누락/미실행, 위험·전달·롤백·다음 행동, 템플릿 절·Issue/AC·승인 경계·문서 로컬 상태를 모두 보존했다. 가상 입력 1개에 대한 반복 결과이며 실제 원격 PR 생성·호스트 자동 스킬 선택·모든 작성 상황의 일반화 증거는 아니다.
