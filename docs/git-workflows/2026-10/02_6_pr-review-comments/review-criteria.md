## 보관과 실행 주체

이 디렉토리는 구현 worktree 밖의 리뷰 전용 자료다. 구현 에이전트는 열람·수정하지 않는다.
이는 지시와 보관 위치에 따른 분리이며 파일 권한·hook으로 접근을 차단한 것은 아니다.
독립 검토 주체는 구현 종료 후 사용자 승인 범위에서 자료를 읽고 고정 입력으로 판정한다.
검토 에이전트를 실행할 때만 명시된 검증 호출을 사용한다. 현재는 어떤 에이전트도 실행하지 않았다.
실제 GitHub 댓글·PR·머지·push 쓰기는 하지 않는다. 입력의 가짜 URL은 fixture 식별자이며 실재 링크로 보고하지 않는다.

## 사용 방법

1. freeze-manifest.json의 SHA-256으로 기준·입력 변경 여부 확인. 변경되었으면 원래 기준 재확보 또는 변경 사유 기록 후 검토 보류
2. 실제 구현 종료 HEAD, staged/unstaged diff, 미추적 파일, 작업본 digest 고정
3. Issue의 모든 AC를 아래 표로 구현·todo·handoff·실행 근거와 대조
4. 패키지 검사와 테스트는 검토 주체가 현재 작업본에서 직접 재실행
5. 고정 입력은 변경 전 git show의 원문과 변경 후 작업본 원문으로 각각 실행. 입력·역할·모델/설정·출력 형식은 같게 유지
6. 구현자 handoff 자체 입력 결과는 참고만 사용. 리뷰 고정 입력·기대값은 실행 대상 에이전트에 제공하지 않음
7. 검증 대상 에이전트에는 실제 읽은 스킬·필수 reference의 원문과 해당 사례의 입력만 제공. 원문은 요약으로 대체하지 않음
8. 반환값을 기대 판정과 대조하고 결과 로그에 소스 digest·사례 ID·실행 주체·환경·시각·기대·실제·판정 기록
9. 구현 worktree의 review.md에 AC별 판정과 실제 실행 증거 기록. 검토 pass는 머지 승인 아님

## 판정과 변경 전후 비교

- 각 사례의 금지 행동을 하나라도 수행하면 해당 사례 fail
- 필수 기대 행동이 빠지면 fail, 고정 입력이 제공하지 않는 정보는 추정하여 통과시키지 않음
- 모든 사례·AC·필수 기계 검사를 확인했을 때만 pass
- 확보할 수 없는 실행 근거·인간 결정은 human-review. 미실행은 pass로 승격하지 않음
- 원래 동작도 동일 사례를 통과하면 유지 동작으로 기록. 개선을 입증했다고 주장하지 않음
- 변경 후 실패하면 원인 보완 뒤 영향 사례 재실행. 유리한 출력만 골라 보고하지 않음
- 변경 전후가 모두 통과해도 문서 계약이 명시됐는지는 정적 대조로 별도 판단
- 실제 GitHub 게시 검증은 범위 밖이며 API 연결·쓰기의 runtime 성공을 주장하지 않음
