# v0.7.0 — 릴리즈·Issue·PR 작성 기준 통일

릴리즈·Issue·PR에서 사용자가 얻는 결과를 먼저 설명하고, 조건·승인·검증 한계를 원문과 대조한다. 설명 목록은 완결된 문장으로 쓸 수 있으며 제목·달성 조건·짧은 메타데이터의 명사형 기준은 유지한다.

## 문서·사용 안내

- 릴리즈는 핵심 요약, 변경 종류별 사용자 결과, 필요한 전환 안내, 검증·추적 근거 순서로 작성한다. 커밋 제목은 후보를 찾는 데 사용하고 실제 diff와 공개 배포 범위로 포함할 변경을 정한다. 사용자에게 영향이 있는 docs·refactor도 포함한다.
- Issue는 목표·영향 및 제외 범위·관찰 가능한 달성 조건·확인된 사실·참고 링크를 구별한다. PR은 변경 후 동작·현재 검증 결론·위험·다음 행동을 먼저 설명하고, 과거 검증과 현재 미확인을 구별한다.
- 복합 항목은 결과와 각각 판단할 조건으로 나누고 관련 조건은 짧게 연결한다. 작성 뒤 원문과 대조해 승인·기존 내용 보존·전환 조치·미검증 정보가 빠지거나 의미가 바뀌지 않았는지 확인한다.
- Issue·PR 템플릿에는 작성 안내를, 별도 문서에는 전후 예시를 제공한다. 기존 템플릿의 절·Issue 연결·AC 필드를 유지하며 생성·댓글·머지·종료의 승인 경계는 바꾸지 않는다.
- Issue·PR·릴리즈 설명 목록에 문장형을 허용한다. 모든 목록에 강제하지 않으며 plan·task·review·commit 목록과 제목·짧은 값·AC의 기존 명사형 기준은 유지한다.

## 전환 안내

- 기존 설치자는 Claude Code와 Codex에서 플러그인을 0.7.0으로 재설치하고 새 세션에서 규칙을 로드한다. 설치된 버전·활성 상태와 캐시 파일 일치를 별도로 확인한다.
- 프로젝트에 이미 설치한 Issue·PR 템플릿은 자동 갱신하지 않는다. 갱신이 필요하면 `workflow-init`에 템플릿 설치를 요청하고 해당 프로젝트의 기존 내용과 선택 범위를 확인한다.
- 과거 v0.3.0·v0.5.0·v0.6.0 릴리즈 노트 개정안은 저장소의 초안만 포함한다. 이번 발행으로 과거 공개 Release 본문이나 태그를 수정하지 않는다.

## 검증과 근거

- 공개 v0.6.0(`e79013a`) 이후 사용자 영향 범위는 [PR #30](https://github.com/insung/git-workflow/pull/30)의 작성 기준·안내 변경이다. 구현 통합 커밋은 `f0ce36a`이며 이번 버전 패키지는 그 변경을 0.7.0으로 구분한다.
- 이번 패키지의 구조 검사·기존 35개 테스트·diff 검사는 통과했다. 기존 스킬 파일은 HEAD와 바이트가 같으며 새 지시 변경은 없다. 발행·설치는 아직 대기 상태다.
- PR #30의 독립 검토는 warn이다. 과거 선행 계획·검토 기준 커밋 이탈과 PR 작성 검증의 RED2·3 후시점 실행 이력을 보존한다. 변경 전 시간 순서 준수는 1/3이며 사전 3회 완료로 표현하지 않는다.
- PR #30에서 실제 플러그인 재설치·호스트 자동 호출·공개 Release 반영은 미실행이었다. 당시 구조·회귀 검사와 초안 대조는 모든 프로젝트의 작성 품질이나 실제 호스트 호출을 증명하지 않는다. 발행 전 패키지 검증 결과와 당시 전달 상태는 [구현 인계](handoff.md)에 별도로 기록한다.
