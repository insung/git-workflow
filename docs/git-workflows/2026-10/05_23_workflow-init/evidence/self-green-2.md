# Public self scenario execution 2

가상 입력에 대한 첫 응답과 예정 행동이다. 실제 대상 변경·네트워크 호출·사용자 질문은 실행하지 않았다.

## PUBLIC1

먼저 설치할 항목을 선택해 주세요: Issue·PR 템플릿, AGENTS.md 채택 선언, GitHub 라벨, 자동 릴리즈 노트 분류 설정. 여러 항목을 선택할 수 있습니다.
행동: 대상은 /fixture/project (origin: example/project). 선택 미응답이므로 파일·디렉터리·원격 라벨을 생성하거나 변경하지 않는다.

## PUBLIC2

GitHub 라벨만 대상으로 example/project의 차이를 미리 봅니다. 기존 bug의 사용자 정의 설명·색상은 그대로 보존합니다. 누락된 release(릴리즈 준비 및 버전 관리, BFD4F2), deployment(설치 배포 및 운영, 006B75)의 생성안을 제시합니다.
행동: 정본 YAML 검증과 기본 미리보기 후 전체 기존 목록을 대조한다. 항목 선택과 누락 생성 승인은 구분하므로 제시한 누락 생성 범위에 대한 명시적 승인을 받기 전 --apply는 실행하지 않는다. 승인 뒤 write 권한 범위에서 해당 누락만 생성하고 재조회한다. .github·AGENTS.md·템플릿·릴리즈 설정은 만들지 않는다.

## PUBLIC3

template-init 호환 진입점으로 템플릿만 설치합니다. 기존 .github/ISSUE_TEMPLATE/feature_request.md는 이름과 내용을 보존하고 FEATURE_REQUEST.md를 추가하지 않습니다. 없는 BUG_REPORT.md와 .github/PULL_REQUEST_TEMPLATE.md만 설치합니다. 배경→목표, 완료 기준→달성 조건은 같은 정보를 요구하므로 누락으로 보고하지 않습니다.
행동: 저장소와 기존 템플릿 위치를 읽고 필요한 디렉터리를 만든 뒤 없는 두 정본만 복사한다. 기존 기능 템플릿의 diff와 의미 대응을 보고하며 영향 범위 등 나머지 필수 절은 실제 내용으로 판단한다. remote 없음은 복사 중단 사유가 아니다. 라벨 미확인: remote 없음. 라벨 생성과 기타 초기화는 실행하지 않는다.

## PUBLIC4

workflow-init의 AGENTS.md 항목으로 아래 추가안을 제시합니다. 대상: /fixture/project/AGENTS.md. 위치: 기존 파일 끝에 구분용 빈 줄을 두고 추가하며 기존 바이트를 보존합니다.

```markdown
## Git workflow

이 프로젝트는 git-workflow를 따른다.
Issue 생성 → plan 작성 → 별도 에이전트 구현 → 메인 독립 검증 → PR 검토 → 사용자 승인 후 머지 → Issue 종료 순서로 진행한다.

- 메인 에이전트는 Issue·plan, 구현 위임, 검증, PR 생성·검토, 승인 후 머지와 실제 머지 확인 뒤 Issue close·결과 기록을 조정한다. 직접 구현하지 않으며, 구현 전에 검토 기준·검증 입력을 고정하고 고정 상태를 확인한다. 고정이 미확인이면 구현 위임을 보류한다.
- Issue 기반 구현 요청에서는 이전 대화를 상속하지 않는 별도 구현 에이전트를 생성해 승인된 단계를 반복 지시 없이 위임한다. 위임 메시지에 공통 목적·유지할 결정·담당 범위와 읽기 순서(Issue → plan 공통 맥락·결정·단계 → 담당 task → handoff·공개 리뷰 지적)를 반드시 명시한다. 비공개 검토 기준·검증 입력은 구현자에게 전달하지 않는다.
- 구현 에이전트는 task-implement에 따라 구현·자체 테스트·결과 인계를 담당한다. 메인은 인계 결과를 고정 기준으로 독립 검증하며, 실패하면 구현자에게 수정을 위임한 뒤 재검증한다.
- 기본 역할 분리와 단계 진행은 요청 범위와 행동·대상별 승인을 따른다. 읽기 전용 질문·Issue 작성만 요청한 경우에는 구현으로 확대하지 않는다.
```

이 경로·전문·위치의 추가안을 승인해 주세요.
행동: 기존 지침과 중복·충돌 여부를 읽어 확인한다. 이 시나리오에는 추가안 승인이 없으므로 파일·디렉터리를 변경하지 않는다. 승인 뒤 재읽기에서 상태가 달라졌다면 새 추가안을 다시 제시한다.
