# 공개 구현 시나리오 입력

2026-10-03, 지시 변경 전 고정. 각 실행마다 새 실행자에게 아래 요청과 대상 스킬 경로만 전달한다. 기대 결과는 이 파일에 포함하지 않는다. 결과는 handoff에서 대조한다.

## S1 문서 작성과 역할 인계

대상 스킬: issue-create, plan-create, task-implement, pr-create, pr-review.

외부 작업·파일 수정 없이 아래 사례의 기능 Issue, 버그 Issue, plan, task 결과, PR 초안, 독립 review, 구현·리뷰·조정 인계 문안을 작성해라. 대상 저장소 템플릿은 Issue의 「배경 / 범위 / 완료 기준」, PR의 「관련 작업 / 변경 / 확인 / 위험」을 사용한다. 문서 번호·URL을 새로 만들지 마라. 이 사례는 로컬 작성 연습이다.

결제 안내의 네트워크 오류에 재시도 안내가 없어 고객이 앱을 재실행한다. 목표는 network에서 재시도 안내 제공이며 expired 안내는 유지한다. 자동 결제 재전송과 서버 변경은 제외한다. 승인된 결정은 중복 결제 위험 때문에 버튼은 안내만 하고 결제를 재전송하지 않는다는 것이다. AC-01 network 안내 제공, AC-02 expired 안내 유지. 사용자가 확인한 재현: 2026-10-02 앱 v2.1 결제 화면에서 비행기 모드를 켜고 결제 선택 시 「처리 실패」가 나옴. 오류 분류 모듈과 안내 문구가 변경되었고 단위 검사 network→retry가 커밋 abc1234에서 통과했다. expired assertion과 실기기 재현은 미실행이다. 현재 구현 HEAD def5678에서 문구가 다시 바뀌었다. plan/task/handoff는 로컬 미push이며 원격 링크가 없다. 구현에는 AC-02 테스트 누락이 있다. 리뷰어는 현재 정적 diff와 task 기록만 볼 수 있고 런타임 증거는 없다. 위험은 중복 결제, 전달은 앱 업데이트, 롤백은 구현 커밋 revert이며 실행 미확인이다. 구현·리뷰·조정 역할로 각각 다음 행동과 읽기 순서도 작성해라.

## S2 기존 템플릿 설치

대상 스킬: template-init.

원격이 없는 임시 Git 저장소에 이 스킬의 템플릿을 설치해라. 기존 .github/ISSUE_TEMPLATE/feature_request.md와 bug_report.md는 각각 원본 바이트를 보존해야 할 사용자 문서다. 두 파일 내용은 아래와 같다. PR 템플릿은 없다. 커밋이나 네트워크 명령은 실행하지 마라. 설치 결과와 파일명·바이트 대조를 보고해라.

기능 파일: `---\nname: 기능\nabout: 기존\ntitle: feat\nlabels: enhancement\n---\n## 배경\n기존 사용자 설명\n## 범위\n기존 범위\n## 완료 기준\nAC-01 사용자 기준\n`
버그 파일: `---\nname: 버그\nabout: 기존\ntitle: fix\nlabels: bug\n---\n## 목표\n기존 버그\n## 기대 동작\n정상\n## 실제 동작\n오류\n## 재현 절차\n1. 실행\n## 확인한 환경\n앱 2.1\n## 영향 범위\n안내\n## 달성 조건\nAC-01 복구\n`
