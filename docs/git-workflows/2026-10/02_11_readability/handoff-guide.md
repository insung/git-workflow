# 역할별 인계 안내

plan은 공통 진입점이다. 이 안내는 역할별 읽기 순서와 전달 항목만 정의한다. 에이전트를 자동 생성하거나 실제 구현·리뷰가 실행됐다는 기록이 아니다. 한 세션으로 진행할 때도 기존 독립 검토 경계는 유지한다.

## 현재 상태

- Issue: [#11](https://github.com/insung/git-workflow/issues/11)
- 준비된 단계: 01 → 02 → 03
- 완료: Issue·검토·계획 작성
- 미실행: README·스킬·템플릿 구현, 새 작성 시나리오, 구현 후 독립 리뷰
- 작업 브랜치: docs/readability-plan, base main
- 독립 입력 브랜치: review/issue-11
- 원격 문서: 미push. 로컬 ref와 문서로 인계하며 공개 링크로 가장하지 않음

## 읽기 순서

| 역할 | 읽을 순서 | 읽지 않을 대상 | 반환할 결과 |
| --- | --- | --- | --- |
| 구현 | Issue → plan 공통 맥락·결정·단계 → 담당 task → 기존 handoff·공개된 리뷰 지적 | review/issue-11와 그 worktree, review-criteria·review-input | 변경 커밋·task 검증 결과·handoff·남은 일 |
| 리뷰 | Issue → plan 공통 맥락 → diff·task·handoff → 독립 기준·입력 | 구현자의 자기 검증만으로 독립 판정 대체 | 대상 커밋·판정·문제·필요 조치·근거 |
| 조정 | Issue → plan → 역할별 진행 결과 | 독립 입력을 구현자에게 전달 | 담당 범위·의존성·통합 상태·다음 행동 |

독립 기준을 작성하거나 읽은 세션은 구현 역할을 맡지 않는다. 시나리오 실행자에게는 요청문·대상 스킬만 주고 기대 결과·다른 실행 결과를 주지 않는다.

## 전달할 항목

- 대상 저장소·worktree·브랜치·정확한 시작 커밋
- Issue와 plan·담당 task 위치
- 담당 단계·변경 파일 경계·앞 단계 완료 여부
- 읽을 문서·역할별 접근 제외 대상
- 검증 방법·완료 판단·현재 미검증
- 이미 승인된 행동과 남은 승인 범위

공통 목적은 plan 링크로 전달한다. 인계 요약이 plan과 충돌하면 실행을 멈추고 충돌을 확인한다. 짧은 요약만 전달해 중요한 결정 이유를 생략하지 않는다.

## 이번 작업의 배정 경계

01·02·03은 의존하는 순차 단계다. 파일이 겹치는 동시 수정은 피한다. 병렬 배정이 필요하면 조정 역할이 파일 경계와 합칠 순서를 먼저 정한다. 합친 결과의 최종 HEAD를 다시 검증한다.

push·PR·머지·Release·설치는 별도 요청이다. 완료 worktree는 결과·보존 필요 파일을 확인한 뒤 이번 대상만 정리한다.
