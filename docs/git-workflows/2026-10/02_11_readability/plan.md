# 문서 가독성 개선 계획

## 요청

> 1. git-workflow 에 README 문서를 개선 + 추가된 스킬 업데이트
> 2. 깃헙 이슈, PR 의 내용이 사람이 읽기가 힘든데 개선 방법 있는지 검토
> 3. 이 작업은 새로운 워크트리 생성하여 진행해주고, 완료된 워크트리는 삭제 처리

현재 진행 범위는 Issue·검토·계획까지다. 구현 단계의 입력은 준비됐으며 미결정 사항은 없다. 실제 구현은 별도 세션에 인계한다.

## 중요한 맥락과 결정

| 확인한 맥락 | 결정 | 이유 |
| --- | --- | --- |
| 조사 기준 main `a0be2fa`에는 새 스킬 3개가 이미 README에 연결됨 | 사용 안내·요청 예시 중심 개선 | 목록을 추가하는 것만으로 사용 흐름이 명확해지지 않음 |
| 기존 Issue·PR에 요구·과정·검증 이력이 함께 나열됨 | 문서별 정보 경계 설정 | 독자의 판단에 필요한 내용부터 읽을 수 있게 함 |
| 표로 바꿔도 한 칸에 여러 주장이 섞임 | 한 항목에 한 주장, 초안 뒤 편집 | 표현 형식보다 정보 단위를 개선 |
| 중요한 근거를 모두 지우면 판단 이유가 사라짐 | Issue에 핵심 맥락, plan에 결정 이유, 상세는 근거 링크 | 간결함과 추적 가능성 함께 유지 |
| 기존 템플릿이 설치된 저장소 존재 가능 | 자산만 대문자로 변경, 기존 설치는 보존 | 이름 차이로 덮어쓰기·중복 생성 방지 |

위 관찰은 정적 검토다. 사용자 읽기 시간·이해도는 측정하지 않았다. [상세 검토](readability-assessment.md)와 [조건 개정 기록](ac-change-record.md)을 참조한다.

## 문서별 정보 경계

| 문서 | 핵심 내용 | 항목 단위 |
| --- | --- | --- |
| Issue | 문제·범위·완료 결과 | 하나의 완료 결과 |
| PR | 변경·검증 결론·위험 | 하나의 결과 또는 위험 |
| plan | 결정·단계·의존성 | 하나의 결정 |
| task | 작업·검증·결과 | 하나의 작업 또는 검증 결과 |
| review | 판정·문제·필요 조치·근거 | 하나의 지적 |

구현 방법과 검증 절차를 달성 조건 한 문장에 넣지 않는다. 필수 사실·AC·재현·미검증·위험·승인 경계는 보존한다. 상세 근거를 반복하기보다 정본을 연결한다.

## 범위

포함: README 두 언어판, 5종 문서 작성 지침, 공통 작성·편집 기준, Issue 주석, 템플릿 대문자 파일명, 참조·검사·예시.

제외: 다른 기존 원격 기록 수정, #6 댓글 규칙·#8 정리 기능 구현, 스킬 이름·승인·판정 규칙 변경, Release·설치 갱신.

서버·데이터 영향은 없다. 기존 저장소 템플릿·AGENTS.md·다른 작업은 보존한다.

## 전달과 롤백

- 계획·task는 작업 브랜치에 보존
- 고정 검토 기준은 review/issue-11에만 보존. 작성·열람 세션은 구현하지 않음
- 구현·push·PR·머지·Release·설치는 별도 요청 범위
- 이번 완료 worktree 삭제는 요청 범위. 보존 필요 파일 확인 후 force 없이 제거
- 롤백은 해당 구현 커밋 revert. 다른 작업 reset·clean 없음
