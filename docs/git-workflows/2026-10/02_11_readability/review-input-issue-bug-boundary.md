# TC-R03 고정 입력: 버그 Issue 재현·범위 보존

새 실행자에게 「입력」과 대상 스킬만 전달해 초안을 받는다. 리뷰 세션이 결과를 판정한다.

## 입력

대상 스킬: issue-create. 아래 실제 조사 자료를 기준으로 버그 본문 초안만 작성한다. 실제 GitHub 생성은 하지 않는다.

기존 템플릿 절: 목표·영향 범위·재현 절차·기대 동작·실제 동작·확인한 환경·달성 조건. 동일 Issue 없음 확인. 2026-10-02 staging의 모바일 Safari에서 파일 업로드→취소→다시 업로드 시 버튼이 비활성 상태로 남음. 기대는 취소 후 재업로드 가능, 실제는 페이지 새로고침 전까지 불가. 데스크톱 브라우저 재현은 미확인. 운영 영향·운영 재현도 미확인. 수정 범위는 취소 후 UI 상태 복구, 서버 재전송·파일 삭제는 제외. 파일 데이터 마이그레이션 없음. AC-01 취소 후 재업로드, AC-02 기존 업로드 완료 흐름 유지. 원격 자료 링크 없음.

## 기대 지적

| ID | 지적 또는 기대 출력 | 근거 | 기대 판정 |
| --- | --- | --- | --- |
| F1 | 재현·기대·실제·확인 환경 유지 | 조사된 사실 | 압축하며 재현 정보 삭제하면 fail |
| F2 | 데스크톱·운영 미확인을 표시하고 추측하지 않음 | 확인 경계 | 전 브라우저 재현·운영 정상 주장하면 fail |
| F3 | 범위·AC-01·02와 마이그레이션 없음 유지 | 달성 조건 | AC 약화·제외 범위 누락하면 fail |

지적하지 않아야 하는 것: 운영·데스크톱 미확인이 있다는 이유만으로 조사된 staging 초안 작성 자체를 차단하지 않음.

## 통과 기준

| 기준 | 조건 |
| --- | --- |
| 필수 | 독립 새 실행자 3회 모두 F1~F3의 기대 동작 충족 |
| 필수 | 지시 변경 전 RED와 변경 후 GREEN의 실제 실행 시점·소스 커밋·출력 기록. 변경 전부터 충족한 동작은 억지 실패를 만들지 않고 유지 증거 기록 |
| 참고 | 글자 수·단어 수 감소는 보조 관찰이며 의미 보존의 통과 근거 아님 |
