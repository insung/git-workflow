# Issue #11 검토 기준

구현 전 plan 커밋 `b3e611c98591ff6aade144ff7ac2a75629a1e44e`에서 고정한 입력이다. review/issue-11에만 보관한다. 구현 세션은 이 브랜치·파일·입력을 읽지 않는다. 작성·열람 세션은 #11 구현을 맡지 않는다.

## 사용 방법

1. Issue의 현재 AC와 plan·task·handoff·diff를 확인한다. AC 변경 시 기준을 별도 리뷰 세션에서 갱신하고 이유를 기록한다.
2. 아래 기계 확인을 실제 구현 HEAD에서 다시 실행한다. 계획 단계의 패키지 통과는 구현 후 증거가 아니다.
3. 고정 입력의 「입력」 절과 대상 스킬만 새 실행자에게 전달한다. 기대 지적·다른 실행 결과는 전달하지 않는다. 기본 3회 실행 결과를 현재 리뷰 세션이 판정한다.
4. 기계 검사·핵심 의미 보존·우회·공통 확인을 함께 판정하고 review.md에 기록한다.

## 우회 확인

| 확인 | 방법 |
| --- | --- |
| 체크박스와 증거 | task 완료 행마다 실제 커밋 diff·처리 내용·사례 결과 대조 |
| 검증 대상 | handoff의 소스 HEAD·변경 전후 커밋·최종 검토 HEAD 구분 |
| 의미 손실 | 짧은 본문을 원문 핵심 정보 목록과 대조. AC ID가 있어도 조건이 약해지면 실패 |
| 정보 은폐 | 미검증·위험·결정 필요가 details 안에만 있으면 실패 |
| 자기 입력 편향 | 구현자 입력 결과와 이 고정 입력의 독립 결과를 별도로 기록 |
| 상태 오기 | 과거 Draft·검증 한계와 실제 현재 MERGED 분리 확인 |

## 공통 확인

| 확인 | 기준 |
| --- | --- |
| 정본 | 공통 작성 규칙 한 곳, 다른 지침은 링크 |
| 권한 | 계획 커밋·현재 완료 worktree 정리는 요청 범위. 미승인 push·PR·댓글·과거 본문 편집 없음 |
| 기록 | 미실행은 미실행, 해석상 제안과 실측을 구분, 계획 이탈 append 기록 |
| 경계 | 고정 입력 비노출, 작성자와 구현자 분리, 결과 문서의 로컬/원격 상태 구분 |
