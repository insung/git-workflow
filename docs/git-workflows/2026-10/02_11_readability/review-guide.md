# 짧은 독립 review 작성 방식

현재 구현 리뷰 결과가 아니라 Issue #11에서 적용할 기록 방식이다. 목적은 task의 실행 결과를 다시 정리하는 것이 아니라 요구 충족·검증 누락·부작용을 독립적으로 판단하는 것이다.

## 최소 기록

- 검토 대상: 실제 소스 커밋과 작업본 범위
- 판정: 기존 pass·warn·fail·human-review 중 해당 값과 이유
- 문제와 조치: 발견했을 때만 작성
- 미검증·사람 결정: 존재할 때 명시
- 근거: task·handoff·독립 검증 결과 링크

문제가 없으면 대상·판정·근거와 검토 한계를 짧게 남긴다. 수행한 작업·테스트 목록·AC 전문을 다시 복사하지 않는다. 명확한 판정에 필요한 짧은 AC별 결과 또는 근거 대응은 유지한다.

## 지적 단위

| 문제 | 근거 | 필요한 조치 |
| --- | --- | --- |
| 하나의 결함 | 위치·관찰 결과 | 하나의 해결 행동 |

하나의 행에 서로 다른 결함을 묶지 않는다. 상세 재현·명령·로그는 근거 문서로 연결한다.

## task와 구분

| task | review |
| --- | --- |
| 계획한 검증의 기대·실제 결과 | 그 검증이 요구를 충분히 확인하는지 판단 |
| 실행 주체의 결과 기록 | 독립 검토와 누락·부작용 확인 |

가독성을 위해 검토를 생략하거나 task 통과를 그대로 pass로 복사하지 않는다. 원격 Review·댓글 게시는 별도 요청 범위다.

## 읽을 맥락

공통 목적과 유지할 판단은 [plan](plan.md#공통-맥락)을 읽는다. 독립 입력은 [인계 안내](handoff-guide.md)의 리뷰 역할에서만 접근한다. 공통 맥락 전문은 반복하지 않는다.
