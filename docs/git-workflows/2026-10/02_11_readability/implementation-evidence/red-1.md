AC-02 유지 assertion을 추가하고 최신 HEAD에서 network 안내·expired 유지·재전송 금지를 확인한다. 실제 명령·환경·시각과 실행 커밋을 handoff에 기록하고 실기기 증거를 보완한다. 수정 후 새 HEAD를 고정해 재검토한다. 승인 결정은 이미 확정되어 같은 결정을 다시 물을 필요가 없다. 리뷰 결과는 머지 승인이 아니다.

| 역할 | 읽기 순서 | 다음 행동 |
| --- | --- | --- |
| 구현 | Issue의 의도·AC → plan의 단계·결정·전달 → 현재 task의 작업·검증 → handoff → 공개된 fail/human-review review | expired assertion 보완, 최신 HEAD 검사, task/plan 상태와 handoff 증거 갱신. 독립 검토 기준·고정 입력과 해당 리뷰 브랜치는 읽지 않음 |
| 리뷰 | Issue → plan·관련 task → 고정된 검토 기준이 있으면 그 기준 → handoff → 현재 diff·assertion·실행 증거 | 수정 HEAD 고정, AC별 구현·테스트·실행 증거 교차 확인, 누락과 미검증 분리, 결과 기록 |
| 조정 | Issue의 요청·범위 → plan의 결정·단계 → task 현황 → handoff의 증거·승인 범위 → review의 지적·다음 행동 | 구현 보완 인계, 증거 확보 조건 정리, 최신 HEAD 재검토 연결, 원격 문서 연결 준비 상태 확인 |

독립 검토 기준을 작성하거나 읽은 세션은 구현을 맡지 않는다. 이번 연습은 실제 리뷰 브랜치·고정 입력을 만들거나 읽지 않았다. 조정 담당은 구현 완료·검토 완료·앱 전달 완료를 구분하고, 현재 누락을 완료로 표시하지 않는다.

Git 루트 확인, remote -v(빈 출력), 현재 브랜치 main, 작업본 상태 ?? .github/를 확인했다. 커밋과 네트워크 명령은 실행하지 않았다. 입력의 \\n 표기를 개행으로 해석해 UTF-8 원본 파일을 만들었다.

- 복사: `.github/PULL_REQUEST_TEMPLATE.md`
- 유지: `.github/ISSUE_TEMPLATE/feature_request.md`, `.github/ISSUE_TEMPLATE/bug_report.md`
- PR 복사 결과: 스킬 정본과 바이트 일치
- 추가 별도 이름의 Issue 템플릿: 없음
- 다른 위치의 기존 PR 템플릿: 없음
- 라벨 미확인: remote 없음, enhancement/bug 조회 미실행

각 Issue 파일에 diff -u로 정본과 차이를 확인했다. 기능 파일은 front matter의 name/about/title과 본문 안내 문구가 다르고 labels는 enhancement로 같다. 버그 파일도 name/about/title과 안내 문구가 다르고 labels는 bug로 같다. 두 파일 모두 기존 사용자 본문을 유지했다.

| 대상 | 정본 절 → 기존 절 | 근거 |
| --- | --- | --- |
| 기능 | 목표 → 배경 | 사용자 설명이 들어가는 문제 배경 자리 |
| 기능 | 영향 범위 → 범위 | 이번 작업의 범위를 기록하는 자리 |
| 기능 | 달성 조건 → 완료 기준 | AC-01 사용자 기준을 기록하는 자리 |
| 버그 | 목표, 기대 동작, 실제 동작, 재현 절차, 확인한 환경, 영향 범위, 달성 조건 → 동일 제목 | 정본의 필수 제목 전체 존재 |

뜻이 같은 절을 필수 절 누락으로 보고하지 않았다. 판단 보류와 누락 필수 절은 없다. 선택 절인 지금 알고 있는 것·참고 링크가 없는 것은 누락이 아니다. front matter 필수 키 name/about/title/labels는 두 파일 모두 있다. 제목과 안내 내용의 차이를 근거로 사용자 파일을 수정하지 않았다.
