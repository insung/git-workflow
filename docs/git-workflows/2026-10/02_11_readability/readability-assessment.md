# Issue·PR 가독성 검토

2026-10-02 실제 원격 본문과 main `a0be2fac9e750a71c91e70344eebd4681c6921b6`을 확인한 정적 검토다. 아래는 작성 기준 제안과 발췌 예시이며 기존 GitHub 본문을 수정하지 않았다. 사용자 읽기 시간·이해도는 측정하지 않았다.

## 결론

본문 첫 문단에서 문제와 바뀌는 결과를 설명하고, 독자가 완료·머지 여부를 판단하는 정보는 펼친 상태로 남긴다. 상세 구현 경로·명령·실험·과거 이력은 정본 문서 링크로 연결한다. 링크로 전달할 수 없는 부가 설명에만 접는 영역을 사용한다.

README 두 언어판에는 13개 스킬과 agents-init·task-implement·issue-close가 이미 존재한다. 목록 추가보다 단계별 요청 예시와 새 스킬의 역할 구분을 개선할 필요가 있다. 미머지 #6·#8의 기능은 현재 사용 가능한 기능처럼 안내하지 않는다.

## 원인과 개선 방법

| 관찰 | 확인한 근거 | 개선 방향 |
| --- | --- | --- |
| 요구 결과와 세부 구현 경로가 같은 층위에 나열 | Issue #8의 포함 목록 9개, AC 9개 | 영향 범위는 사용자 결과 중심으로 묶고 AC는 각 ID·검증 조건 유지 |
| 검증 사실·과거 이력·현재 판단이 긴 목록에 섞임 | PR #9 검증 상태·위험과 전달 | 현재 결론→통과 범위→남은 검증→근거 순서 |
| 내부 용어를 알아야 판단 가능 | PR #9의 HEAD·human-review·독립 모의 행동 | 첫 등장에 뜻을 설명하고 검토 대상 커밋을 한 곳에서 연결 |
| 자세한 문서 링크·커밋이 본문을 압도 | PR #9 계획과 검토 근거 | 계획·인계·검토의 대표 링크 우선. 단계별 링크는 계획 표에서 탐색 |
| 템플릿은 짧게 쓰라고 해도 우선순위·압축 기준 부족 | PR template·writing-conventions | 공통 문체 정본에 의미 보존·판단 정보 노출 기준 추가 |

행 수·글자 수만 줄이는 방법은 권하지 않는다. 완료 조건이나 미검증을 삭제하면 판단 품질이 낮아진다. 고정 글자 수 제한·이모지 필수화·항상 접기·모든 내용을 표로 바꾸기도 채택하지 않는다.

## 정보 배치 제안

| 펼친 본문에 유지 | 정본 문서 링크 우선 | 링크로 부족할 때 접는 상세 |
| --- | --- | --- |
| 문제·원하는 결과, 포함·제외·영향, AC ID, 관련 Issue, 바뀐 결과, 현재 검증 결론, 미검증·위험·필요 결정·전달·롤백 | 단계별 작업·테스트 사례, 상세 명령·환경·전체 commit, 과거 검토·승인 이력 | 보조 기술 설명·참고 자료 |

AC는 풀어쓴 조건마다 ID를 그대로 유지한다. 짧은 요약만으로 완료를 판정하지 않는다. 범위를 좁혀 다시 쓴 경우 의미 변경으로 취급하며 기존 조건을 유지한 것처럼 보고하지 않는다.

## 개선 전후: Issue #8의 영향 범위

출처: [Issue #8](https://github.com/insung/git-workflow/issues/8). 아래는 영향 범위만 재구성한 예시다. 원문의 목표·AC-01~AC-09·호환성·운영 영향·참고 링크는 별도로 유지해야 한다.

### 개선 전

원문은 pr-merge, 원격·로컬 브랜치, worktree, 보호 대상, squash/rebase, 실행 위치, 권한, 후속 Issue, issue-close 인계를 각각 긴 목록으로 설명한다. 서로 연결된 조건을 독자가 직접 묶어 읽어야 한다.

### 개선 후 후보

포함

- **머지 후 정리**: 실제 머지를 확인한 작업의 원격·로컬 브랜치와 워크트리를 구분해 정리하고 각각 결과를 재확인
- **작업 보존**: 기본·base·장기 유지·보호 브랜치, 다른 작업 사용, dirty·미추적·보존 필요 ignored 파일, 후속 커밋을 확인하고 보류. squash/rebase의 비조상 관계를 강제 삭제 근거로 사용하지 않음
- **실행 방법**: 일반 Git·Codex 관리 worktree를 구분하고 안전한 실행 위치로 이동 또는 인계. 승인된 정리 범위에서만 실행
- **후속 작업과 결과 인계**: 작은 변경도 같은 해결 범위인지 확인해 열린 Issue를 재사용하거나 새 Issue로 연결. 실제 머지·정리 근거는 #5의 issue-close에 전달하고 자동 닫힘의 결과 코멘트 보완 경로 연결
- **사용 안내와 검증**: 관련 README·공통 참조·정상 및 보류 시나리오 갱신

제외

- #4의 기존 AC 변경·재오픈, #5의 종료 기능·양식 중복 구현, #6의 댓글 규칙 변경
- 자동 head 삭제 설정 변경, 다른 작업 일괄 삭제, force 삭제·보호 규칙 우회
- 이 지침 개선 과정에서의 실제 PR 머지·기존 브랜치 및 worktree 삭제·Release

### 유지 확인

목록 묶음은 읽기 경로의 개선안이다. 원문의 AC 9개와 운영 설명에는 auto-merge·merge queue 대기, reviewed HEAD 대응, 다른 PR 사용, 공유·잠김 worktree, 이미 삭제·실패 결과, 머지와 정리의 결과 분리, 권한과 실제 원격 실행 경계가 남아야 한다. 해당 조건을 영향 범위 요약에서 모두 재서술할 필요는 없지만 Issue 전체에서 삭제하면 안 된다.

## 개선 전후: PR #9의 검증 상태

출처: [PR #9](https://github.com/insung/git-workflow/pull/9). 2026-10-02 실제 상태는 MERGED다. 아래 예시는 **PR 생성 당시 검증 요약**의 재구성이며 현재 PR을 Draft로 되돌리거나 머지 미완료라고 주장하지 않는다.

### 개선 전

> 최종 검토 상태: **human-review**. 통합 전 행동 결과는 과거 증거이며 통합 HEAD의 고정 입력 재실행은 미실행이다.

패키지 25/25, 통합 전 행동 25개, 오류 보완, 과거·통합 HEAD 구분, 실제 GitHub 검증이 다른 항목에 흩어져 있다.

### 개선 후 후보

**생성 당시 결론: 사람 판단 필요(human-review).** 구조 검사는 통과했지만, 최신 main을 합친 구현의 독립 행동 검증은 다시 실행하지 않았다.

- **통과**: 통합 구현 `9999759`의 패키지 검사·Node 테스트 25/25·diff 검사
- **과거 근거**: 통합 전 모의 행동 25개 통과. 코멘트 게시 실패 보고 누락 1건을 보완해 관련 범위를 재검증했으나 통합 구현의 검증을 대신하지 않음
- **미검증**: 통합 구현의 고정 입력 재실행, 실제 GitHub 공동 작성자 표시·Issue 종료 및 코멘트 적용·플러그인 호스트 로딩
- **담당자**: 생성 후 실제 지정 여부 재조회 필요
- **환경**: spec-it 미채택. 지시 문서이므로 구조 검사와 독립 모의 실행 사용

전체 실행 근거는 원문에서 확인한 [구현 인계](https://github.com/insung/git-workflow/blob/e451004d9514f8a1d2ba69f63b7794d8b6010d93/docs/git-workflows/2026-10/02_5_issue-close/handoff.md)와 [검토 결과](https://github.com/insung/git-workflow/blob/e451004d9514f8a1d2ba69f63b7794d8b6010d93/docs/git-workflows/2026-10/02_5_issue-close/review.md)로 연결한다.

### 유지 확인

이 예시는 검증 절만 바꾼다. 원문의 Issue #5·AC-01~09 해결 범위, 변경 결과, 기준 커밋, 비공개 입력의 분리, 생성 당시 Draft 인계와 별도 머지 승인 필요, 후속 설치·호스트 확인, 서버 배포 없음, 기존 main 기능·0.4.0 유지와 revert 롤백은 PR 전체에 유지해야 한다. 과거 상태와 현재 MERGED는 구분해 기록한다.

## 구현 방식 비교

| 방법 | 판단 | 이유 |
| --- | --- | --- |
| 기존 Markdown 템플릿과 공통 문체 개선 | 채택 제안 | 현재 CLI·필수 검사와 연결 가능, 서술 품질 직접 개선 |
| 상세 정본 링크·필요 시 details | 채택 제안 | 판단 정보 노출과 상세 근거 접근을 함께 유지 |
| Issue Forms 전환 | 이번 범위 제외 | 입력 누락 방지에는 유용하지만 서술 품질의 직접 해결책이 아니며 신규 양식·CLI 경로 대조 필요 |
| 기존 모든 원격 본문 일괄 편집 | 제외 | 사람의 기록과 다른 진행 작업을 바꾸며 이번 요청의 검토 범위를 초과 |

GitHub 공식 문서는 [details·summary의 접는 영역](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/organizing-information-with-collapsed-sections)과 [템플릿·Issue Forms](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/about-issue-and-pull-request-templates)을 지원한다. 어떤 정보를 먼저 노출할지는 이 프로젝트의 작성 정책 제안이며 GitHub가 강제한 규칙은 아니다.
