<summary>개정 전 조건 원문: 의미 보존 대조용</summary>

- [ ] AC-01: 두 README의 흐름·스킬 목록·사용 예시가 같은 내용이며, agents-init·task-implement·issue-close의 역할과 요청 예시를 현재 스킬과 대조 가능
- [ ] AC-02: 실제 Issue·PR의 읽기 어려운 원인과 개선 전후 예시를 기록하고, 원문의 의도·범위·완료 조건·미검증·위험을 유지
- [ ] AC-03: 공통 문체에 결과 중심 요약, 쉬운 용어, 중복·빈 절 제거와 상세 근거 분리 기준을 한 번만 정의하고 작성 지침에서 연결
- [ ] AC-04: Issue·PR 템플릿과 작성 지침에 개선 기준을 적용하되 AC ID·관련 Issue·검증 상태·위험·전달·확인된 링크와 기존 템플릿 우선 규칙 유지
- [ ] AC-05: README 대조·상대 링크·패키지 검사와 스킬 작성 시나리오의 변경 전후 검증 수행. 미실행은 통과로 기록하지 않음
- [ ] AC-06: 새 워크트리에서 작업하고 결과를 보존한 뒤 해당 작업의 완료된 워크트리만 삭제. 다른 작업의 브랜치·워크트리·변경 보존
- [ ] AC-07: Issue는 문제·범위·완료 조건, PR은 변경·검증·위험, plan은 결정·단계·의존성, task는 작업·검증·결과, review는 판정·문제·조치를 중심으로 기록. 공통 규칙과 각 작성 지침에 정보 경계·단일 주장·결론 우선·중복 제거·작성 후 편집 단계 반영
- [ ] AC-08: 기능·버그 Issue 템플릿에 위 작성 원칙을 짧은 HTML 주석으로 안내. 사실·AC·재현·미검증·위험을 삭제하거나 숨기도록 유도하지 않음
- [ ] AC-09: Issue 템플릿 자산을 `FEATURE_REQUEST.md`·`BUG_REPORT.md`로 변경하고 링크·복사 안내·패키지 검사·테스트 갱신. 소문자 중복 자산과 깨진 참조 없음, 기존 설치 템플릿 보존
