# 문서 정본과 원격 요약

Issue/PR 생성·구현 기록·검토 결과를 GitHub에 남길 때 읽는다. 상세 정본은 대상 리포 docs/git-workflows/의 plan, todo, handoff, review다. 원격에는 이번 결과·판단·남은 일의 핵심 요약과 근거 문서 링크를 남긴다. 문서 전문을 복사하지 않는다.

## 원격 기록 형태

```markdown
## 진행 요약

01 단계의 재시도 조건과 테스트 사례를 구현했다. 최종 통합 검증은 미실행이다.

## 근거 문서

- [계획](<확인된 원격 plan URL>)
- [01 작업과 사례별 결과](<확인된 원격 todo URL>)
- [검토 결과](<확인된 원격 review URL>)

## 남은 일

- 현재 HEAD의 통합 검증
```

Issue 원문은 요청/달성 조건 정본, plan은 승인된 실행 설계 정본이다. 의미 있는 범위 변경은 두 곳에 요약·링크로 연결하고 이전 결정과의 차이를 기록한다. 문서가 길다는 이유로 별도 요약 파일을 매번 만들지 않는다.

## 링크를 만들기 전

- GitHub 본문에 로컬 절대 경로나 `file://`를 넣지 않는다. docs 파일의 tracked 상태, 실제 commit과 원격에 있는지, 대상 독자의 접근 가능성을 확인한다.
- 검증 결과는 `https://github.com/<owner>/<repo>/blob/<검토한-commit>/<문서경로>`처럼 검토한 커밋에 저장된 문서 내용의 확인된 고정 링크(permalink)를 우선한다. 현재 계획을 가리키는 브랜치 링크와 검증 당시 내용을 고정한 커밋 링크를 구분한다.
- 초기 Issue는 문서 커밋 이전에 만들 수 있다. 그때는 핵심 요청과 `계획 문서 링크 준비 중` 상태를 먼저 남기고, 승인된 commit/push로 문서가 접근 가능해진 뒤 링크를 갱신한다. 전문 복사로 대체하지 않는다.
- untracked·미push·비공개 접근 불가이면 링크를 검증된 것처럼 쓰지 않는다. 로컬 대화에는 상대 경로와 `로컬 초안` 상태를 전달하고 원격에는 링크 대기/접근 제한을 표시한다. 링크 생성 목적의 push도 승인 범위를 확인한다.
- 진행 댓글·본문 갱신은 해당 행동이 요청에 포함된 경우에만 실행한다. Issue/PR 생성·검토·머지 승인은 댓글 신규 게시·수정 승인으로 확대하지 않는다. 이미 승인된 동일 댓글 행동·대상·범위는 반복 승인 없이 적용한다. 신규 게시 요청을 기존 댓글 수정 권한으로 확대하지 않는다. 기존 인간 본문과 다른 작업의 댓글을 덮어쓰지 않는다.
- 근거 문서를 담은 문서-only 후속 commit이 검토 HEAD와 다르면 검토 HEAD와 문서가 저장된 증거 commit을 각각 적는다. 해당 permalink가 증명하는 실행 대상은 문서 속 HEAD·작업본 근거로 대조하며, 문서 commit 자체를 재검토한 HEAD로 바꾸지 않는다.

## 문서별 역할과 읽기 순서

| 문서 | 독자가 찾을 답 | 상세 정보의 위치 |
| --- | --- | --- |
| Issue | 문제·포함/제외·완료 결과와 핵심 맥락 | 조사 전문은 확인된 참고 문서 |
| PR | 바뀐 동작·검증 결론·남은 위험과 리뷰 요청 | 실행 상세는 task·handoff |
| plan | 공통 목적·유지할 판단·결정 이유·단계 의존성 | 단계별 작업·검증은 task |
| task | 실제 작업·검증·결과와 계획 이탈 | 상세 실행 출력·환경은 handoff |
| review | 독립 판정·지적·필요 조치·근거·검토 한계 | task 표를 복사하지 않고 관련 결과 연결 |

plan에 `공통 맥락`을 두고 목적, 유지할 판단과 사용자 결정을 모든 역할의 진입점으로 연결한다. 구현 방법·검증 상세를 각 문서에 되풀이하지 않는다. 중요한 결정 이유는 plan에 남기고 Issue·PR에서 그 판단에 필요한 맥락만 요약한다.

| 역할 | 읽을 순서 | 반환할 결과 |
| --- | --- | --- |
| 구현 | Issue → plan 공통 맥락·결정·단계 → 담당 task → handoff·공개 리뷰 지적 | 변경 커밋·실제 검증 결과·미검증·다음 단계 |
| 리뷰 | Issue → plan 공통 맥락 → diff·task·handoff → 독립 기준·입력 | 대상 HEAD·독립 판정·문제·조치·근거·한계 |
| 조정 | Issue → plan → 역할별 결과 | 담당 범위·단계 의존성·통합 상태·다음 행동 |

인계에는 공통 목적·유지할 결정의 plan 위치, 담당 단계·파일 경계, 읽을 순서, 현재 HEAD, 완료/미실행, 승인 범위와 다음 행동을 담는다. 짧은 인계가 정본의 중요한 결정을 대신하지 않는다. 비공개 검토 기준·입력은 구현 역할에 전달하지 않으며 [실행 경계](execution-boundaries.md)를 유지한다.
