# 기록의 정본과 연결

Issue는 요청·기준·계획, PR은 실제 구현·검증·검토·전달 결과의 기본 진입점이다. 작업별 plan·task·handoff·review는 자동 생성하지 않는다. [상세 설계 조건](../../plan-create/references/plan.md#상세-plan-생성-조건)과 아래 증거 기준으로 필요한 자료만 분리한다.

## 문서별 역할과 읽기 순서

| 위치 | 남길 답 |
| --- | --- |
| Issue | 원문, 왜·무엇을 바꿀지, 영향·제약·AC, 현재 계획, 남은 결정, 참고 링크 |
| PR | 실제 변경과 중요한 선택 이유, 계획 대비 차이, AC별 결과·미검증, 위험·배포·다음 조치 |
| 선택적 plan | 본문에서 분리한 설계·의존성·중요한 결정 이유 |
| 선택적 task | 독립 역할에 전달할 작업 경계·검증 계약 |
| 검토 결과 | 대상 HEAD·독립 판정·조치·근거·한계. 대화 또는 요청된 PR 리뷰 기록 |

기본 읽기 순서는 Issue → PR과 diff·검증 근거다. 구현은 Issue의 준비된 계획과 제약을 읽고, 역할별로 담당 범위를 추가한다. 별도 plan·task가 실제 연결되어 있을 때만 읽는다. 기존 작업은 [기존 작업 재개](../../plan-create/references/plan.md#기존-작업-재개)의 순서를 따른다. 인계는 Issue URL·담당 범위·유지할 결정·base/HEAD·증거 위치·미실행·승인 범위·다음 행동만 연결한다.

PR 생성 전 결과는 대화나 작업용 임시 초안으로 유지한다. 원격 PR 생성 시 필요한 결과를 본문에 반영한다. 임시 초안은 공유 정본으로 취급하지 않으며 다른 세션에는 실제 접근 가능한 입력을 전달한다.

## 증거와 실행 로그

별도 설계가 있다는 이유로 evidence/·evidences/·txt·digest 파일을 생성하지 않는다. 확장자보다 쓰임과 보존 필요를 판단한다.

| 자료 | 보관 기준 |
| --- | --- |
| 핵심 결과 | PR에 AC·기대/실제·pass/fail/not-run·명령/확인 방법·대상 commit과 필요한 환경·시각·미실행 이유를 필요한 만큼 기록 |
| 제품 테스트·반복 재현 fixture | tests 등 프로젝트의 기존 경로에서 코드와 함께 유지 |
| 일시 명령 출력·작성 실행 결과 | 작업용 임시 경로. 커밋·공유 문서에 전문 복사하지 않음 |
| 외부 상태·복잡한 실패를 입증하는 고유 자료 | 다시 얻기 어렵고 판정에 필요할 때만 비밀값을 제거한 최소 자료를 접근 가능한 영구 위치에 보존 |
| 비공개 독립 검토 입력 | [검토 보관 위치](../../plan-create/references/review-criteria.md#보관-위치)에서 공개 기록과 분리 |

임시 경로는 사용자·리뷰어가 읽을 영구 링크가 아니다. PR에 필요한 요약·재현 방법과 실행 대상이 남아 있으면 원시 로그 전체를 보존하지 않아도 된다. 임시 자료만으로 주장하는 결과는 검증 근거 부족으로 기록한다. 다시 실행하기 어려운 고유 증거는 영구 보관 또는 확보 전까지 미확인으로 남긴다. 세션 재개에 필요한 자료가 다른 환경에 없으면 접근 부족을 기록하고 다시 확보한다.

기존 docs/git-workflows 파일과 고정 링크는 당시 증거로 보존한다. 새 방식 적용만으로 삭제·이름 변경하지 않는다. 별도 정리 요청이 있을 때만 참조·고유 정보·진행 중 작업·보존 상태를 조사한다.

## 링크를 만들기 전

- 실제 원격 Issue·PR·commit과 접근 가능한 파일만 연결한다. 참고 링크 절은 Issue에서 필수이며 링크가 없으면 `확인된 참고 링크 없음`으로 쓴다.
- 로컬 미push 문서·임시 경로·비공개 입력에 원격 URL을 만들어 넣지 않는다. 공유 기록에 머신 절대 경로·비밀값·원시 로그를 넣지 않는다. 사용자가 준 요청 원문의 경로는 원문 인용이며 AI가 생성한 근거 링크와 구별한다.
- 실행 증거는 확인한 commit permalink를 우선한다. 최신 계획 링크와 검증 당시 고정 자료를 구별한다. 문서-only 후속 commit이 있으면 코드 검증 대상과 문서 보존 commit을 각각 표시한다.
- Issue·PR 본문 갱신, 댓글 신규 게시·수정, push는 해당 행동의 승인 범위에서만 실행한다. 생성·검토·머지 승인을 댓글 권한으로 확대하지 않는다. 기존 인간 본문·다른 작업 댓글을 덮어쓰지 않는다.

## 문서 허브 인계

별도 document-handoff 파일을 기본 생성하지 않는다. 원천 Issue·PR와 실제 배포 확인 자료로 아래 최소 정보를 전달한다.

- 기획 식별자·문서 링크, 이번 구현 결과와 중요한 결정 이유
- 현재 코드·구성·인프라 정의와 관련 저장소/commit
- 실제 배포 대상·버전·확인 시점·근거 또는 배포 대기·미확인
- 운영·롤백·남은 일과 원천 Issue·PR 링크

코드에 배포 설정이 존재한다는 사실을 실제 인프라 배포 완료로 쓰지 않는다. 머지·테스트 통과도 실제 배포 증거가 아니다. 문서 허브는 기획별 현재 구현·운영 상태를 갱신하며 전체 작업 로그를 복사하지 않는다. 실제 허브 작성·동기화는 요청된 범위에서만 실행한다.
