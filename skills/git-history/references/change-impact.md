# 제안된 변경의 영향 조사

사용자가 변경 영향을 요청했을 때만 읽는다. [git-history](../SKILL.md)의 읽기 전용 경계와 [탐색 참조](investigation.md)를 그대로 적용한다. 의도 설명만 요청하면 이 경로를 추가하지 않는다.

## 현재 코드와 제안 대조

제안한 변경의 대상·전후 동작을 확인한다. 무엇을 바꾸려는지 모호하여 영향 결론이 달라지면 필요한 질문 하나만 확인하고 가능한 조사는 이어간다. 과거 의도의 기준 OID와 영향 판단에 쓰는 **현재 코드 기준**을 구별한다. 현재 기준은 생략하면 HEAD로 고정하고 가정을 밝힌다. 관련 미커밋 변경이 있으면 기준 OID·작업본/index diff를 구별하여 함께 대조한다. 과거 PR의 파일 목록을 현재 영향 범위로 대신하지 않는다.

대상 함수·조건·동작에서 시작하여 실제 호출 코드·설정·테스트로 범위를 좁힌다. 해당 분기의 입력·출력, 오류·경계값, 소비자가 기대하는 계약과 유지 조건을 제안된 변경과 비교한다. 직접 호출, 설정에 따른 활성 경로, 현재 회귀 테스트의 주장으로 연결되는 부분부터 확인하며, 간접 호출이나 외부 소비자를 확인할 수 없으면 그 범위를 미확인으로 남긴다. 질문에 필요한 계약을 설명할 수 있으면 종료하며 전체 저장소·전체 이력 탐색을 강제하지 않는다.

역사 기록은 유지할 계약의 이유를 설명하는 근거다. 최초 요청과 후속 요청을 구별하고, 현재 코드·설정·테스트가 그 계약을 유지하는지 대조한다. 필요한 원문 링크만 확인하며 접근 제한을 영향 없음으로 바꾸지 않는다.

## 영향 보고와 구현 인계

결론과 판단에 필요한 근거를 먼저 제시한다. 고정 양식을 채우려고 영향·테스트·수치를 만들지 않는다.

- 제안된 동작 차이와 영향을 받는 현재 호출 경로·설정·테스트의 위치
- 유지할 조건과 바뀔 수 있는 계약, 정적 분석의 예상 영향·불확실성
- 확인된 과거 의도·후속 결정과 제안된 변경의 관계
- 관련 기존 테스트와 필요한 정상·실패·경계 검증안, 실제 실행 여부
- 구현 승인 범위와 인계할 중요한 공백 또는 계획 이탈

조사 자체는 수정·커밋·원격 게시를 하지 않는다. 테스트는 먼저 검증안으로 제시하며 자동 실행하지 않는다. 별도로 승인된 재실행이 있으면 그 범위와 결과를 표시한다. 정적 예상, 과거 PR에 기록된 통과, 현재 직접 실행 결과를 구별한다.

같은 대상·범위의 구현 승인이 이미 있으면 재사용하여 기존 구현 절차로 인계한다. 같은 승인을 다시 요구하지 않는다. 새 중요 영향·계획 이탈·승인되지 않은 결정이 있으면 해당 부분만 확인한다. 구현 승인이 없으면 영향 보고로 종료하며 영향 질문을 수정 권한으로 해석하지 않는다. 별도 Issue 생성·댓글 게시·설치도 조사 요청에 포함하지 않는다.
