# 종료 코멘트 양식

Issue를 닫거나 이미 닫힌 Issue에 결과를 보완할 때 읽는다. 코멘트는 결과 요약과 근거 링크만 담는다. plan·todo·handoff 전문은 복사하지 않는다. 링크 규칙은 [document-links](../../git-workflow/references/document-links.md)를 따른다.

## completed

```markdown
## 종료 결과

<무엇이 바뀌었는지 한두 문장>

- 해결 PR: <PR URL>
- merge commit: <hash>
- 배포 상태: <배포 완료 / 배포 대기와 이유 / 배포 없음과 이유>

## 달성 조건 결과

| AC | 결과 | 근거 |
| --- | --- | --- |
| AC-01 | 충족 | <PR·검토 결과 또는 필요한 기존 문서의 확인된 근거> |

## 작업 정리

| 대상 | 결과 | 근거 또는 이유 | 다음 행동 |
| --- | --- | --- | --- |
| <정확한 작업 워크트리 또는 원격 head 식별값> | <워크트리: 삭제 / 이미 없음 / 보류 / 실패 / 미확인 / 해당 없음. 원격 head: 이미 없음 / 남음 / 미확인> | <전후 조회의 확인 결과 또는 승인·보존·도구 제약/오류> | <남은 확인·보존·승인·인계. 없으면 없음> |

## 후속 작업

- <후속 Issue URL과 한 줄 설명. 없으면 없음>
```

AC 표에는 Issue 본문의 모든 AC ID를 쓴다. 결과는 충족만 허용한다. 미충족·미확인 AC가 있으면 completed로 닫지 않는다 ([차단 조건](../SKILL.md#completed-차단-조건)).

정리 표는 이미 CLOSED인 Issue의 completed 결과 보완에서도 필수다. 각 대상의 결과를 별도 행으로 쓴다. 원격 head는 PR마다 저장소·head 이름·OID로 행을 두고 [원격 head 잔여 확인](../SKILL.md#원격-head-잔여-확인)의 조회 결과를 쓴다. `남음`은 조회 시점에 ref가 있다는 보고이며 issue-close가 삭제하지 않는다. `해당 없음`은 이 작업에서 워크트리를 생성·사용하지 않은 경우에만 대상 확인 근거와 함께 남긴다. 결과와 근거는 [머지 후 작업 정리](../../pr-merge/references/post-merge-cleanup.md)를 따른다. `삭제`는 실행 후 성공한 조회에서 대상 부재를 확인한 경우, `이미 없음`은 식별된 작업 워크트리는 실행 전, 원격 head는 issue-close의 조회에서 대상이 없음을 성공한 조회로 확인한 경우다. 머신 절대 경로 대신 원격 기록에서 대상이 구별되는 저장소·작업 branch·HEAD·worktree 식별값과 접근 가능한 PR·검토 기록 또는 기존 handoff 근거 링크를 사용한다.

삭제 질문에 거절한 대상은 `보류`·삭제 거절과 보존을 기록한다. 답변이 없는 대상은 `보류`·승인 대기와 다음 행동(사용자 답변 대기)을 기록한다. 같은 정확한 대상의 기존 승인이나 실행 전 부재 조회로 질문이 필요 없었던 경우에는 해당 근거를 기록한다. 질문 자체를 삭제 승인이나 완료 근거로 쓰지 않는다.

정리 보류·실패·미확인을 AC 충족이나 Issue 종료 상태로 바꾸지 않는다. 정리 결과 자체는 새 completed 차단 조건이 아니지만 삭제가 AC라면 기존 차단 조건을 적용한다.

## not planned

```markdown
## 종료 사유

<진행하지 않기로 한 이유>

- 결정: <결정한 역할과 결정 위치(대화·회의록·댓글 링크)>
- 대안: <대신 진행하는 Issue·방법. 없으면 없음>
- 다시 열 조건: <상황이 바뀌면 다시 검토할 조건. 없으면 없음>
```

## duplicate

```markdown
## 종료 사유

#<정본 Issue>와 해결 범위가 같아 그 Issue에서 진행한다.

- 옮긴 정보: <이 Issue에만 있던 재현 정보·요구사항. 정본 Issue에 옮긴 댓글 링크. 없으면 없음>
```

`--duplicate-of`가 타임라인에 중복 관계를 남긴다. 이 Issue에만 있던 정보는 닫기 전에 정본 Issue로 옮긴다.

## 작성 기준

- 개인 이름 대신 역할을 쓴다.
- 확인하지 못한 배포·테스트 결과는 미확인으로 쓴다.
- 링크는 원격에서 접근 가능한 것만 쓴다. 로컬 경로를 쓰지 않는다.
