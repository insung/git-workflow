# PR 검토 댓글

PR의 일반 대화 댓글에 최초 검토·재검토 결과 또는 머지 직전 확인을 남길 때 읽는다. 공식 Review 제출·approve·request changes와 인라인 댓글은 이 규칙의 대상이 아니다.
공통 원격 기록 형태·요약 범위·permalink·링크 대기·게시 권한의 정본은 [document-links](../../git-workflow/references/document-links.md)다. 아래는 그 공통 구조 안에 담는 PR 전용 내용이다. plan·todo·handoff·review 전문을 복사하지 않는다.

## 담당과 시점

| 기록 종류 | 담당 | 시점 | 댓글 요청이 없을 때 |
| --- | --- | --- | --- |
| 최초 검토 / 재검토 | pr-review | 검토 HEAD와 AC별 근거·판정을 고정한 뒤 | 대화 또는 요청된 review.md로 반환 |
| 머지 직전 확인 | pr-merge | 실제 PR HEAD·검토 결과·남은 위험·머지 승인 상태를 다시 확인한 뒤, 머지 실행 전 | 대화로 확인 결과 반환 |

pr-create의 기본 기록은 PR 본문과 handoff다. 필요성을 확인한 별도 인계 댓글이 요청되면 공통 기록 규칙을 적용하고, 검토 결과를 만들어 게시하지 않는다.
검토 댓글은 Issue 종료 코멘트가 아니다. 종료 사유·해결 PR·merge commit·배포 상태는 PR 검토 양식의 필수 필드로 만들지 않는다.

어떤 HEAD든 검토·댓글 게시 요청이나 승인이 있다는 이유만으로 검토 완료나 판정을 추정하지 않는다. 댓글 행동의 승인 여부와 검토 완료 여부는 별개이며, 이전 검토 승인·머지 승인도 pass의 증거가 아니다. 기존 검토 결과를 요약할 때도 해당 HEAD의 결과와 AC별 근거를 확인할 수 없으면 미확인으로 적는다. 새 HEAD의 검토 결과와 AC별 근거가 확보되지 않았으면 이전 HEAD의 pass를 재사용하거나 새 HEAD의 pass를 만들지 않고, 미확인·재검토 필요와 필요한 근거를 반환한다. 판정 조건은 [pr-review 결과](../SKILL.md#6-결과)를 따른다.

## PR 전용 내용

공통 「진행 요약」에는 다음 내용을 넣는다. 최초·재검토는 Issue 본문의 **모든 AC ID**를 빠짐없이 요약한다. 증거 부족·미실행은 미확인으로 적으며 완료로 바꾸지 않는다.

```markdown
- 기록 종류: <최초 검토 / 재검토 / 머지 직전 확인>
- 대상 PR: <실제 PR URL>
- 검토 HEAD: <전체 commit hash>
- 결과: <pass / warn / fail / human-review>
- 이전 기록: <재검토인 경우 확인된 이전 댓글 URL; 최초면 없음>

| AC | 결과 요약 | 근거 |
| --- | --- | --- |
| <Issue의 모든 AC ID> | <충족·미충족·미확인과 핵심 이유> | <확인된 고정 링크 또는 링크 대기/접근 제한> |

- warn: <머지를 막지 않는 위험; 없으면 없음>
- 검토 결과는 사용자 머지 승인이 아니다.
- 머지 승인 상태: <승인됨과 대상 PR/HEAD·방식 / 미승인 / 확인 불가>
```

공통 「근거 문서」에는 확인된 review·handoff·todo 등의 permalink를 넣고, 「남은 일」에는 보완·재검토·미실행을 적는다. 없으면 없음으로 쓴다. 링크가 준비되지 않았으면 링크 대기/접근 제한으로 표시하고 로컬 경로·허구 URL·전문 복사로 대체하지 않는다. 링크를 위한 자동 commit/push도 하지 않는다.
머지 직전 확인은 기존 검토 댓글/근거를 연결하고 같은 검토 HEAD의 현재 결과·남은 위험·승인 상태와 실제 PR HEAD 일치를 요약한다. 모든 AC 검토를 새로 했다고 주장하지 않는다. 검토 HEAD 뒤 커밋은 [기록 커밋](../SKILL.md#7-기록-커밋) 규칙으로 먼저 대조한다. 인정되는 기록 커밋은 검토 HEAD와 확인한 PR HEAD를 구분해 표시한다. 그 밖의 HEAD 변경이면 재검토 필요와 실제 HEAD를 보고하고 pr-review로 인계한다.

## 신규 게시·수정·생략

기존 댓글은 대상 PR, 전체 검토 HEAD, 기록 종류, 판정·AC 요약·warn·남은 일·근거와 작성 주체를 대조한다. 실행 계정이 같다는 이유만으로 이 워크플로우의 댓글이라고 판단하지 않는다. 작성 이력/기록 종류/대상을 확인할 수 없으면 수정하지 않고 확인 필요로 반환한다.

| 조건 | 행동 |
| --- | --- |
| 해당 종류의 최초 기록 없음 | 신규 게시 요청 범위에서 새 댓글 |
| 기록 커밋 규칙에 해당하지 않는 새 HEAD 또는 같은 HEAD라도 판단·근거가 실질적으로 변경됨 | 이전 기록 보존, 이전 댓글 URL을 연결한 새 댓글 |
| 같은 HEAD·종류·실질 결과의 오탈자·표현·링크 보정만 있음 | 수정 요청 범위에서 해당 워크플로우가 작성한 기존 자기 댓글만 수정 |
| 같은 HEAD·종류·결과·근거로 재실행 | 기존 댓글 URL을 반환하고 재게시 생략 |
| 인간 또는 다른 작업의 댓글 | 보존; 수정 대상으로 선택하지 않음 |

단순 링크 보정은 같은 증거에 대한 주소 보정이다. 새로운 실행 증거·새 판단을 추가하거나 링크 대기에서 확인된 증거로 판단이 바뀌면 실질 변경으로 취급한다. 최초 검토와 머지 직전 확인은 종류가 다르므로 서로 덮어쓰지 않는다. 과거 PR 댓글을 일괄 소급 수정하지 않는다.

## 실행과 확인

1. 사용자 댓글 요청의 행동(신규 게시/수정), 대상 저장소·PR, HEAD·기록 종류와 내용 범위를 확인한다. PR 생성·검토·머지 승인만 있으면 쓰지 않는다. 같은 행동·대상·범위의 승인은 반복 확인하지 않는다. 승인 범위 밖 행동이 필요하면 로컬 초안과 필요한 행동을 반환한다.
2. 실제 PR HEAD와 기존 댓글 목록·본문·작성자·URL을 조회한다. 필요한 페이지를 모두 확인하고 관련 댓글의 소유·종류·결과를 대조한다. 조회 불가·불완전이면 중복 없음으로 추정하지 않고 게시/수정을 보류한다. 검토 HEAD 뒤의 기록 커밋 여부를 먼저 대조한다. 기록 커밋으로 인정되지 않은 최초/재검토 결과의 검토 대상이 변경되었으면 현재 결과를 새 HEAD에 재사용하지 않고 게시를 보류하며 재검토로 인계한다. 머지 직전 확인 기록은 예외로, 불일치 자체를 요청된 확인 결과로 기록할 수 있다. 이때 검토 HEAD와 실제 PR HEAD를 모두 적고 머지 보류·재검토 인계를 명시한다. 기존 판정은 이전 검토 HEAD의 결과임을 표시하고 새 HEAD의 판정·승인을 만들지 않는다.
3. 위 표로 신규/수정/생략을 결정한다. 자기 댓글 확인 또는 이전 기록 URL을 확보하지 못하면 필요한 확인을 보고한다.
4. 승인된 행동만 실행한다. 응답 불명/시간 초과/exit 0만으로 성공이라 하지 않는다. 즉시 재실행하지 말고 기존 댓글을 재조회해 대상 PR·HEAD·종류·본문이 일치하는지 확인한다. 게시/수정 여부를 확인할 수 없으면 미확인으로 멈추고 중복 위험과 필요한 조회를 보고한다. 미게시가 확인된 경우에만 승인 범위에서 재시도한다.
5. 신규 게시·수정 후에도 URL과 실제 저장된 본문을 조회해 의도한 내용과 일치하는지 확인한다. 확인된 URL·신규/수정/생략 결과를 반환한다. URL 또는 실제 내용 미확인은 그대로 보고하며 완료를 주장하지 않는다.
