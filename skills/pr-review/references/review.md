# PR 검토 결과 양식

Issue 없는 PR 예외(경미한 정합성 보완·순수 릴리즈 준비)이면 아래 템플릿의 Issue·AC 항목에 대체 기록의 확인 가능한 요청 근거·범위·검증을 대응시킨다. 조건은 [Issue 연결 검사](../../git-workflow/references/issue-link.md)를 따른다.

[공통 작성·편집 기준](../../git-workflow/references/writing-conventions.md#정보-단위와-작성-후-편집)을 적용한다. review는 독립 판정과 필요한 조치를 전달한다. task 작업·검증 표나 handoff 실행 이력을 다시 복사하지 않는다. 짧아도 대상·판정·근거·한계는 생략하지 않는다.

```markdown
# PR 검토 결과

결과: <pass / warn / fail / human-review>. <판정 이유 한 문장과 다음 행동>

- 담당·부모 Issue / PR / 기존 연결 기록: <참조>
- base / 검토 HEAD / commit 범위 / 확인 시각: <실제로 확인한 대상>
- 미커밋 변경: <없음 또는 파일과 patch/digest>
- 의도 출처: <Issue의 기준·계획, 연결 문서 또는 의도 부족>
- 검토 기준: <기준 commit·위치 또는 없음>
- 검토 한계: <미실행·접근 불가·현재 HEAD와 다른 증거>

## 지적과 필요한 조치

<!-- 문제가 없으면 생략. 지적 하나마다 독립적으로 처리할 수 있는 한 문제 -->

- <AC/TC ID>: <위치와 관찰한 실패 동작>. <영향과 필요한 수정·증거>. 근거: <확인한 참조>

## 독립 대조 요약

| AC·시나리오 | 구현·assertion 근거 | 현재 실행 근거 | 판정 |
| --- | --- | --- | --- |
| <AC-01, 정상·실패·경계·유지 중 하나> | <구현 위치·테스트 assertion 위치 또는 없음> | <현재 HEAD 결과·근거 링크 또는 미실행> | <충족 / 충족(배포 뒤 확인 대기) / 테스트 누락 / 구현 누락 / 미검증> |

- 계획 대조: <누락·계획 밖 변경·계획의 검증 누락 또는 일치의 근거 링크>
- 고정 입력 재실행: <있을 때만 입력 식별자·AC·실행 주체·횟수·대상 commit·결과 요약과 허용된 근거 위치>

## 다음 행동

- <담당 작업의 보완·추가 증거·사람 결정 또는 검토 완료 후 다음 단계>
- 적용 HEAD·재검토 조건: <대상과 변경 시 조건>
- 머지 승인: <승인 상태; 리뷰 결과는 머지 승인 아님>
```

## 작성 규칙

| 항목 | 규칙 |
| --- | --- |
| 판정과 지적 | 결론·필요 조치를 먼저 쓴다. 한 지적에 하나의 문제와 근거·조치를 담는다. 단순 작업 경과는 제외한다. 문제가 없어도 검토 HEAD·판정·근거·한계를 기록한다. |
| AC별 대조 | Issue의 모든 AC를 행으로 쓴다. 한 행에 하나의 판단을 작성하고 필요한 상세 결과가 있으면 연결한다. 대응 assertion이 없으면 근거 칸에 `없음`을 쓴다. |
| 계획 대조 | 계획의 검증 누락은 「계획 대조」 줄에 쓴다. 관련 공개 계획·diff를 연결하고 작업 표를 반복하지 않는다. |
| 실행 근거 | 「현재 실행 근거」 칸에는 검토 HEAD의 결과만 쓰고 과거 commit의 통과는 이력으로 표시한다. 누락·미실행을 축약하며 숨기지 않는다. |
| 고정 입력 재실행 | 실제 주체·횟수·대상 commit·결과를 기록한다. [검증 실행 주체](../../git-workflow/references/execution-boundaries.md#검증-실행-주체)를 따른다. |
| fail·human-review 공개 범위 | 공개되는 문서의 모든 절과 표에 고정 입력의 명령·입력 값·기대 지적·통과 기준을 쓰지 않는다. 결함이 드러난 AC와 실패 동작만 전달한다. 상세 재실행 증거는 독립 검토 보관 위치에 저장하고 구현자의 접근 제외 경계를 유지한다. |
| 규칙 외 의견 | AC·task 근거가 없는 advisory는 판정 지적과 분리한다. 내용이 없으면 절을 만들지 않는다. |

인계는 [역할별 읽기 순서](../../git-workflow/references/document-links.md#문서별-역할과-읽기-순서)를 따른다. 공통 목적·유지할 결정은 Issue와 필요한 상세 설계를 연결하고 독립 입력을 구현자에게 전달하지 않는다.
