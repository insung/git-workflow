# PR 검토 결과 양식

검토 대상 커밋과 미커밋 변경 근거를 먼저 고정한다. 사례별 실행 근거와 정책 원문은 복제하지 않고 링크로 연결한다.

```markdown
# PR 검토 결과

- Issue / PR / plan / todo:
- base / 검토 HEAD / commit 범위 / 미커밋 변경 파일·patch/digest / 확인 시각:
- 의도 출처: <Issue·plan 또는 추정>
- spec-it: <미채택, 또는 manifest/lock 위치와 정책 검사 결과 링크>
- 결과: <pass / warn / fail / human-review>

## AC별 대조

| AC | 기대 시나리오 | 구현 위치 | 테스트·assertion | 실행 결과 | 누락·판단 |
| --- | --- | --- | --- | --- | --- |
| AC-01 | <정상·실패·경계·유지 중 하나> | <파일:줄, commit> | <테스트 파일:줄 또는 없음> | <통과·실패·미실행, 실행 커밋> | <충족 / 테스트 누락 / 구현 누락> |

## 계획 대조

| todo 작업·사례 | 실제 변경 | 판단 |
| --- | --- | --- |
| <01 작업 1, TC-01> | <commit·파일> | <일치 / 빠진 작업 / 계획 밖 변경> |

## 정책 지적

<!-- spec-it 채택 프로젝트에서만 작성. 미채택이면 이 절을 만들지 않음 -->

| Rule ID | 적용 계기·위치·관찰 | 영향 | 상태 | 필요한 결정·증거·수정 |
| --- | --- | --- | --- | --- |

## 규칙 외 의견

<!-- AC·todo·정책 근거가 없는 advisory -->

## 다음 행동

- 수정할 todo와 추가할 테스트:
- 필요한 사람 결정:
- 결과가 적용되는 HEAD와 재검토 조건:
- 머지 승인 상태: 리뷰 결과는 머지 승인이 아님
```

## 작성 규칙

| 항목 | 규칙 |
| --- | --- |
| AC별 대조 | Issue의 AC ID마다 기대 시나리오 하나에 한 행을 쓴다. 대응 assertion이 없으면 테스트 칸에 `없음`, 판단에 `테스트 누락`을 쓴다. |
| 계획 대조 | Issue의 AC ID 중 todo 검증 표에 없는 ID를 `빠진 작업`으로 쓴다. todo 체크 표시는 실제 변경 칸의 근거가 아니다. |
| 실행 결과 | 검토 HEAD와 다른 커밋의 결과는 이력으로 적고 현재 결과로 쓰지 않는다. |
