# spec-it 정책 검사

대상 저장소에 `.architecture/manifest.yaml`과 `.architecture/lock.yaml`이 있을 때만 적용한다. 둘 중 하나라도 없으면 이 절차를 쓰지 않는다.

## 절차

1. 대상 AGENTS.md, manifest, lock, 예외 기록과 lock이 고정한 규칙 원문을 읽는다.
2. 설치된 spec-it-check를 적용한다. 설치되지 않았으면 lock이 고정한 정책 소스의 `skills/spec-it-check/SKILL.md`를 직접 읽는다.
3. 영향 조사가 필요하면 같은 방식으로 spec-it-impact를 찾는다.
4. 설치와 고정 소스 모두 접근할 수 없으면 검사하지 못한 정책 범위를 human-review로 남긴다.

`../spec-it/skills/`는 후보 위치일 뿐이며 모든 환경에 있다고 가정하지 않는다. 임의 설치나 설정 변경을 하지 않는다. 실행하지 않은 검사를 실행했다고 적지 않는다.

## 판정

| 상태 | 조건 |
| --- | --- |
| pass | 고정 규칙을 확인했고 위반이 없음 |
| warn | 규칙이 권고하는 항목의 위험 |
| fail | 고정 규칙 위반 |
| not-applicable | 규칙의 적용 조건에 해당하지 않음 |
| human-review | 결정·증거 부재, 규칙 원문 접근 불가 |

결정·증거 부재나 실행하지 않은 검사는 pass가 아니다.

## 기록

- 정책 지적은 Rule ID·적용 계기·위치·관찰·프로젝트 영향·필요한 결정·증거·수정을 함께 적는다.
- 고정 규칙에 없는 의견은 advisory로 분리한다.
- 규칙을 복제하거나 새로운 의무를 만들지 않는다.
- 검사는 대상 코드·정책을 수정하지 않는다.
- 정책 결과 JSON을 저장할 때는 고정된 spec-it의 스키마와 허용 위치를 따른다.
- 정책 예외는 spec-it의 예외 절차로 기록한다. 리뷰 결과나 머지 승인으로 예외를 만들지 않는다.
