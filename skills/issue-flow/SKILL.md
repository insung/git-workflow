# 목표 단위 진행 흐름 보고

[공통 실행 경계](../git-workflow/references/execution-boundaries.md)를 적용한다.
보고는 읽기 전용이다. Issue·PR·브랜치를 바꾸지 않으며, 만드는 파일은 2절의 기록 파일뿐이다.

보고의 답은 **순서도 + 변경표**다. 지난번 사용자에게 보여 준 판(기준판)과 비교해 진행 위치와 바뀐 것을 알린다.

## 1. 범위

- 범위는 **목표 하나**다. 목표는 한 문장(예: 「일별 배치를 실행해 집계 결과를 DB에 남긴다」).
- Issue 번호로 요청받으면 그 Issue의 목표를 목표로 삼고, 연결된 sub-issue·PR·결정 기록을 노드로 넣는다.
- 그 목표를 위해 열린·닫힌 Issue, 그 Issue들이 낳은 다른 저장소의 Issue·PR, 사용자 결정을 노드로 넣는다.
- 목표와 관계없는 Issue, 언급만 된 아이디어는 넣지 않는다.

## 2. 기록 파일

보고할 때마다 판 번호 n을 하나 올려 두 파일을 남긴다. 이전 판은 지우지 않는다.

| 파일 | 내용 |
| --- | --- |
| `flow-<목표 슬러그>.json` | 목표 문장과 판별 노드 상태 |
| `flow-<목표 슬러그>-v<n>.<확장자>` | 이번에 보여 준 순서도 원본 |

위치는 사용자가 지정한 폴더다. 지정이 없으면 관리 세션의 작업 폴더에 둔다. 대상 저장소에는 커밋하지 않는다.

```json
{
  "goal": "목표 한 문장",
  "versions": [
    {"v": 3, "date": "2026-10-28", "diagram": "flow-daily-batch-v3.svg",
     "nodes": [{"id": "batch#32", "title": "#32 집계 저장",
                "desc": "집계 결과를 DB에 쓴다", "status": "wait_user",
                "deps": ["batch#7"], "evidence": "PR #39 (머지 대기)"}]}
  ]
}
```

`id`는 고정 키다(`<저장소 약칭>#<번호>`, 결정은 `decision:d3`). 제목이 바뀌어도 바꾸지 않는다.

## 3. 상태 값

| status | 뜻 |
| --- | --- |
| done | 원천에서 확인된 완료 |
| now | 하위 세션이 작업 중 |
| wait_user | 사용자 승인·결정·실행 대기 |
| todo | 선행이 끝나지 않아 시작 전 |
| dropped | 하지 않기로 함 |

Issue·PR의 `done`은 GitHub를 다시 조회해 확인한 것만 쓴다(PR MERGED와 merge commit, Issue CLOSED·stateReason COMPLETED). 결정의 `done`은 사용자 답으로 확인한다. 하위 세션 보고만으로 완료로 바꾸지 않는다.

## 4. 순서도에 넣을 것

- 목표 문장
- 노드마다 무슨 일인지 한 줄. 다른 문서를 열지 않아도 알 수 있는 말로 쓴다(예: 「재실행 시 중복 집계 막기」).
- Issue·PR 번호. 번호가 없는 노드는 번호 없이 쓴다.

결정 ID·AC 번호 같은 내부 ID만으로 노드나 변경을 부르지 않는다. 쓸 때는 뜻을 함께 쓴다. 변경표·사용자가 할 일·대기 중 결정에도 같다.

## 5. 보고 순서

1. json의 최신 판과 그 판의 순서도 파일을 읽는다(기준판).
2. 원천을 다시 조회한다: 노드마다 Issue·PR 상태, merge commit. 새 하위 세션 보고와 사용자 결정을 반영한다.
3. 기준판과 비교해 변경을 넷으로 나눈다: **완료됨**(status가 done으로), **새로 생김**(새 id), **바뀜**(제목·설명·deps 변경, 또는 done이 아닌 status 변경), **삭제**(dropped 또는 id 사라짐).
4. 순서도를 그리고 그 아래에 변경표를 붙인다.
5. json에 새 판을 더하고 순서도를 `-v<n>` 파일로 저장한다.

## 6. 출력 계약

답은 이 순서로만 쓴다.

1. **첫 줄:** `v3 → v4: 완료 2 · 새로 1 · 바뀜 1 · 삭제 0` (첫 보고는 `v1: 노드 n개`)
2. **순서도**
3. **변경표** — 변경이 있을 때만

   | 노드 | 지난 판 | 이번 판 | 바뀐 이유 |
   | --- | --- | --- | --- |
   | #32 집계 저장 | todo | wait_user | PR #39 생성, 머지 승인 대기 |

4. **사용자가 할 일** — wait_user 노드만, 노드마다 한 줄(어디서 무엇을)
5. **대기 중 결정** — 결정 노드만, 권장안과 함께

## 자주 하는 실수

| 실수 | 대신 이렇게 |
| --- | --- |
| 기준판을 읽지 않고 처음부터 다시 그린다 | json과 이전 순서도 파일을 먼저 읽는다 |
| 하위 세션 보고만 보고 done으로 바꾼다 | GitHub를 다시 조회한다 |
| 삭제된 노드를 말없이 없앤다 | 변경표에 「삭제 · 이유」로 남긴다 |
| 보여 준 판을 저장하지 않는다 | json에 판을 더하고 순서도 파일을 남긴다 |
