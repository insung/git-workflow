# 마일스톤 운영 설정

이 항목을 선택했을 때만 실행한다. 실제 조회·생성·연결·릴리즈 기준은 [공통 마일스톤 절차](../../git-workflow/references/milestones.md)가 정본이다.

1. 대상 저장소와 기존 마일스톤·정책·태그 관행을 조사한다. 이름 규칙·연결 대상·기한·발행 준비·종료 기준과 초기 생성할 마일스톤을 구분해 제안한다. 과거 버전이나 모든 후보를 미리 생성하지 않는다.
2. 기존 승인된 정책 문서·README 지정 절을 재사용한다. 없으면 README의 `마일스톤` 절을 제안한다. 운영 기준의 파일·절과 읽기 연결은 한 곳을 정본으로 유지한다. Issue 생성·릴리즈 요청이 해당 기준을 읽도록 대상 AGENTS.md에 최소 연결을 제안할 수 있지만 전체 채택 선언을 함께 추가하지 않는다.
3. 파일 쓰기가 필요하면 절대 경로·추가/수정 전문·정확한 위치·기존 내용과 차이를 제시한다. 최초 초기화 요청이나 항목 선택만으로 문서 쓰기를 실행하지 않는다. 같은 대상·내용의 승인이 이미 있으면 재승인하지 않는다. 일부 승인이나 읽기 연결 거절이면 그 부분만 적용하고 미연결을 보고한다.
4. 승인 직전 상태와 적용 직전 파일·링크 대상 상태를 대조한다. 동시 변경·충돌이면 관련 쓰기를 보류하고 새 차이를 제시한다. 기존 바이트를 보존해 승인한 절만 추가/수정하며 이미 같은 내용이면 중복 생성하지 않는다.
5. 초기 마일스톤 생성은 승인된 저장소·이름·설명·기한 범위만 처리한다. 명시적 생성 요청은 해당 범위의 권한으로 재사용한다. 기준 설정 승인을 Issue 연결·기존 메타데이터 교체·이월·종료 권한으로 확대하지 않는다.
6. 정본·읽기 연결·원격 마일스톤을 각각 확인하고 적용/무변경/보류/미확인을 보고한다. 재초기화는 기존 기준과 메타데이터를 보존한다. 문서 존재와 패키지 검사만으로 실제 호스트 준수를 주장하지 않는다.

예시 운영안은 태그와 같은 `vX.Y.Z`, Issue 중심 연결, 합의된 출시일만 기한 지정, 확정 범위 완료·100%와 실제 태그 대조 후 발행, 발행 확인·종료 승인 후 마일스톤 종료다. 저장소 기존 규칙이 우선이며 이 예시를 자동 설치하지 않는다.
