# AGENTS.md 초기화

프로젝트가 git-workflow를 따르며 메인 조정·별도 구현으로 진행한다는 선언과 명시적인 코드 의도·변경 영향 조사의 짧은 호출 안내를 추가한다. 상세 절차는 각 단계 스킬을 정본으로 유지한다.

## 추가 전문

[채택 선언 정본](../assets/agents-declaration.md)을 읽어 대상에 맞춰 제시한다.

여러 프로젝트를 포함하는 루트 대상이면 첫 문장을 `이 루트 디렉토리의 하위 프로젝트들은 git-workflow를 따른다.`로 바꾸고 나머지 선언은 유지한다. 개별 프로젝트에는 위 첫 문장을 쓴다.

역할별 인계는 [문서 읽기 순서](../../git-workflow/references/document-links.md#문서별-역할과-읽기-순서), 공개 기준 충분·별도 입력 고정 완료·필요한 입력 미준비의 구별은 [검증 준비](../../git-workflow/references/execution-boundaries.md#검증-준비), 필요한 기준 고정·비공개 입력 격리는 [검토 입력 보관](../../git-workflow/references/review-criteria.md#보관-위치), 승인과 검증 실행은 [공통 실행 경계](../../git-workflow/references/execution-boundaries.md)를 따른다. 스킬은 지시 모음이며 별도 스케줄러가 아니다.

## 제안과 적용

1. 사용자가 지정한 대상 프로젝트 또는 여러 프로젝트를 포함하는 루트와 `AGENTS.md`의 절대 경로를 확인하고 기존 파일을 읽는다. 기존 내용은 삭제·재작성·재배치하지 않는다.
2. 채택 선언·역할 분리·전체 진행 순서·조사 호출 안내와 공통 작업 단위 기준 한 줄, 위임 지시의 `Issue:` 항목 한 줄을 각각 같은 뜻의 기존 문구와 대조한다. 모두 있으면 추가하지 않고 무변경 결과를 보고한다. 일부만 있으면 없는 문단·줄만 제안하며 선언 전체를 반복하지 않는다. 명시적 Issue 강제 규칙 등 기존 지침과 충돌하면 차이와 필요한 교체안을 제시하고 승인 전 해당 추가·교체를 보류한다. GitHub 보호 설정을 바꾸거나 우회하지 않는다.
3. 기존 파일에는 끝에 추가한다. 조사 안내는 명시 요청의 호출과 승인 범위의 구현 인계만 담고 상세 탐색·영향·종료 기준은 `git-history` 스킬에서 관리한다. 대상에 맞춘 위 전문 또는 누락 문단 외에 상세 정책, 특정 계정·로컬 경로, 자동 커밋 권한을 추가하지 않는다.
4. 제안·승인·적용·확인은 이 스킬 SKILL.md의 「파일 쓰기 승인」을 따른다. 파일이 없었던 경우에만 새 파일을 생성한다.
