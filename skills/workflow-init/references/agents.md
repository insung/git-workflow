# AGENTS.md 초기화

프로젝트가 git-workflow를 따르며 메인 조정·별도 구현으로 진행한다는 짧은 선언만 추가한다. 상세 절차는 각 단계 스킬을 정본으로 유지한다.

## 추가 전문

[채택 선언 정본](../assets/agents-declaration.md)을 읽어 대상에 맞춰 제시한다.

여러 프로젝트를 포함하는 루트 대상이면 첫 문장을 `이 루트 디렉토리의 하위 프로젝트들은 git-workflow를 따른다.`로 바꾸고 나머지 선언은 유지한다. 개별 프로젝트에는 위 첫 문장을 쓴다.

역할별 인계는 [문서 읽기 순서](../../git-workflow/references/document-links.md#문서별-역할과-읽기-순서), 기준 고정·비공개 입력 격리는 [검토 입력 보관](../../plan-create/references/review-criteria.md#보관-위치), 승인과 검증 실행은 [공통 실행 경계](../../git-workflow/references/execution-boundaries.md)를 따른다. 스킬은 지시 모음이며 별도 스케줄러가 아니다.

## 제안과 적용

1. 사용자가 지정한 대상 프로젝트 또는 여러 프로젝트를 포함하는 루트와 `AGENTS.md`의 절대 경로를 확인하고 기존 파일을 읽는다. 대상이 불명확하면 경로를 확인할 때까지 쓰지 않는다. 기존 내용은 삭제·재작성·재배치하지 않는다.
2. 같은 뜻의 채택 선언·역할 분리와 전체 진행 순서가 이미 있으면 중복으로 추가하지 않고 무변경 결과를 보고한다. 일부만 있거나 충돌하는 지침이 있으면 기존 문구와 충돌을 설명하고 추가 여부를 사용자에게 묻는다. 기존 지침을 덮어쓰거나 충돌을 임의로 해결하지 않는다.
3. 쓸 필요가 있으면 **대상 절대 경로, 추가할 전문, 추가 위치**를 제시한다. 기존 파일에는 끝에 추가하며 구분용 줄바꿈도 명시한다. 파일이 없으면 새 파일로 만들겠다고 알린다. 대상에 맞춘 위 전문 외에 상세 정책, 특정 계정·로컬 경로, 자동 커밋 권한을 추가하지 않는다.
4. 제시한 안에 대한 사용자의 **명시적 승인**을 기다린다. 최초 초기화 요청은 추가안 승인으로 간주하지 않는다. 거절하거나 응답이 없으면 파일·디렉터리를 만들거나 변경하지 않는다. 재촉·기본 승인·시간 초과 승인을 적용하지 않는다.
5. 승인 후 파일을 다시 읽어 제안 때의 상태와 비교한다. 파일 생성·삭제나 내용 변경이 있으면 새 상태에 맞춰 경로·전문·위치를 다시 제시하고 승인을 받는다. 상태가 같으면 승인한 추가만 쓰며 기존 바이트를 보존한다. 파일이 없었던 경우에만 새 파일을 생성한다.
6. 기존 내용 보존과 승인한 전문·위치를 확인하고 실제 경로와 변경 결과를 보고한다. 커밋·push·PR·설치까지 실행할 권한으로 확대하지 않는다.
