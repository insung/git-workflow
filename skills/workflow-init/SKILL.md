# 워크플로우 초기화

[공통 실행 경계](../git-workflow/references/execution-boundaries.md)를 적용한다. 초기화는 아래 항목 중 사용자가 선택한 범위로 한정한다.

## 항목 선택

「git workflow 설치해줘」처럼 일반 요청이면 여섯 항목을 제시하고 원하는 항목을 묻는다. **선택을 받기 전에는 파일·디렉터리·원격 라벨·마일스톤을 만들거나 변경하지 않는다.** 선택 메뉴 제시, 기본 전체 설치, 응답 없음·재촉·시간 초과는 선택이나 승인이 아니다. 항목 선택과 최초 초기화 요청은 AGENTS.md·브랜치 전략·마일스톤 기준 문서의 쓰기 승인이 아니며, 그 쓰기는 아래 「파일 쓰기 승인」을 따른다. 템플릿 교체와 라벨 생성 권한은 각 항목 절차를 따른다.
「라벨만 설치해줘」·「템플릿과 릴리즈 설정을 설치해줘」처럼 명시한 요청은 그 항목만 처리한다. 선택하지 않은 항목을 의존성이라는 이유로 함께 설치하지 않는다. 대상 경로나 저장소가 불명확하면 그 정보가 확인될 때까지 파일·디렉터리·원격 라벨·마일스톤을 생성하거나 변경하지 않는다.

| 항목 | 선택 뒤 읽을 절차 | 결과 |
| --- | --- | --- |
| Issue·PR 템플릿 설치·갱신 | [템플릿](references/templates.md) | 없는 정본 설치, 기존 파일은 정본 전체 교체 |
| AGENTS.md 채택 선언 | [선언](references/agents.md) | 경로·전문·위치 제안과 명시적 승인 후 추가 |
| GitHub 라벨 | [라벨](references/labels.md) | 차이 미리보기, 승인된 누락만 생성 |
| 자동 릴리즈 노트 분류 | [릴리즈 설정](references/release.md) | `.github/release.yml` 선택 설치 |
| 프로젝트 브랜치 전략 | [전략 초기화](references/branch-policy.md), [전략 후보](references/branch-options.md) | 관행 조사·전략과 경로·전문·위치 승인 후 단일 정본과 최소 읽기 연결 |
| 마일스톤 운영 설정 | [마일스톤 초기화](references/milestones.md) | 기존 기준 조사, 승인된 이름·대상·기한·종료 기준과 초기 마일스톤만 적용 |

다른 기존 파일이나 메타데이터를 임의로 수정·삭제하지 않는다.

## 파일 쓰기 승인

AGENTS.md 채택 선언, 브랜치 전략 문서, 마일스톤 운영 기준 문서를 쓸 때 적용한다. 템플릿 교체는 템플릿 절차를 따른다.

1. 쓸 필요가 있는 모든 파일의 **절대 경로, 추가·수정할 전문, 정확한 위치, 구분 줄바꿈, 기존 내용과 차이**를 제시한다. 파일이 없으면 새 파일로 만든다고 알린다.
2. 사용자의 **명시적 승인**을 기다린다. 일부 승인이나 읽기 연결 거절은 승인된 부분에만 적용하고 적용하지 않은 부분을 보고한다.
3. 같은 뜻의 내용이 이미 있으면 중복 추가하지 않고, 일부만 있으면 누락만 제안한다. 기존 규칙과 충돌하면 덮어쓰거나 정본을 복제하지 않고 해결안을 승인받는다.
4. 적용 직전 **대상 파일 모두를 다시 읽고** 제안 당시의 존재·내용·링크 대상 상태와 비교한다. 생성·삭제·동시 수정이 있으면 쓰기를 보류하고 새 상태의 경로·전문·위치·차이를 다시 제시하여 재승인받는다.
5. 승인 당시와 같은 파일에만 승인한 추가·수정을 적용하고 그 외 바이트는 보존한다. 적용 후 기존 바이트 보존과 승인한 전문·위치를 확인한다.

## 결과

선택한 항목, 대상 경로·owner/repo, 실제 변경, 유지한 기존 내용과 차이, 미실행 항목과 이유를 보고한다. 로컬 파일 설치와 원격 라벨 생성은 별개 결과로 확인한다.
