# 워크플로우 초기화

[공통 실행 경계](../git-workflow/references/execution-boundaries.md)를 적용한다. 초기화는 아래 항목 중 사용자가 선택한 범위로 한정한다.

## 항목 선택

「git workflow 설치해줘」처럼 일반 요청이면 네 항목을 제시하고 원하는 항목을 묻는다. **선택을 받기 전에는 파일·디렉터리·원격 라벨을 만들거나 변경하지 않는다.** 기본 전체 설치나 응답 시간 초과를 선택으로 간주하지 않는다.
「라벨만 설치해줘」·「템플릿과 릴리즈 설정을 설치해줘」처럼 명시한 요청은 그 항목만 처리한다. 선택하지 않은 항목을 의존성이라는 이유로 함께 설치하지 않는다. 대상 경로나 저장소가 불명확하면 그 정보가 확인될 때까지 쓰지 않는다.

| 항목 | 선택 뒤 읽을 절차 | 결과 |
| --- | --- | --- |
| Issue·PR 템플릿 설치·갱신 | [템플릿](references/templates.md) | 없는 정본 설치, 기존 파일은 정본 전체 교체 |
| AGENTS.md 채택 선언 | [선언](references/agents.md) | 경로·전문·위치 제안과 명시적 승인 후 추가 |
| GitHub 라벨 | [라벨](references/labels.md) | 차이 미리보기, 승인된 누락만 생성 |
| 자동 릴리즈 노트 분류 | [릴리즈 설정](references/release.md) | `.github/release.yml` 선택 설치 |

일반 요청에서 선택 메뉴를 보여주는 것만으로 적용 동의가 성립하지 않는다.

명시적 라벨 설치·생성 요청은 지정하거나 확인한 대상·정의 범위의 누락 생성 권한으로 적용하며, 미리보기 뒤 같은 권한을 다시 묻지 않는다. 정의·대상·부분 범위가 불명확하면 빠진 범위만 확인한다.

AGENTS.md는 경로·전문·위치 추가안의 명시적 승인을 별도로 기다린다. 기존 설정·라벨 메타데이터 교체도 별도 요청 범위를 따른다.

템플릿 설치·갱신 항목을 안내할 때 기존 내용·front matter가 정본 전체로 교체됨을 알린다. 해당 항목 선택이나 명시적 템플릿 설치·갱신·업데이트·교체 요청은 선택한 템플릿의 전체 교체 권한이다. 기존 내용 보존·없는 파일만 설치를 요청하면 참조의 보존 경로를 따른다. 정본 전체 교체와 기존 내용 보존을 동시에 명시하면 충돌하는 파일만 보류하고 확인한다.

다른 기존 파일이나 메타데이터를 임의로 수정·삭제하지 않는다.

사용자가 로컬 작업공간을 지정하면 그 소스의 workflow-init 지침과 자산을 사용한다. 캐시 설치본으로 대체하지 않는다. 템플릿 설치·갱신 구분과 안전한 교체는 [템플릿 절차](references/templates.md)를 따른다.

## 결과

선택한 항목, 대상 경로·owner/repo, 실제 변경, 유지한 기존 내용과 차이, 미실행 항목과 이유를 보고한다. 로컬 파일 설치와 원격 라벨 생성은 별개 결과로 확인한다. 커밋·push·PR·릴리즈 발행·호스트 플러그인 설치는 요청 범위를 따로 확인한다.
