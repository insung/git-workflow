# 선택적 작업 계약

Issue의 계획 또는 상세 plan으로 담당자가 실행할 수 있으면 task 파일을 만들지 않는다. 여러 역할에 독립된 변경 경계·입력·검증을 인계해야 할 때만 `task-{nn}-{step-title}.md`를 만든다. 기존 todo 작업은 [재개 규칙](plan.md#기존-작업-재개)으로 이어간다.

```markdown
# <단계> <결과>

Issue / 계획: <기준 링크>
담당 범위: <확인한 파일·동작과 제외 대상>

## 작업

- [ ] <관찰 가능한 결과>

## 검증

| 사례 | AC | 입력·기대 동작 | 확인 방법 | 실제 결과·대상 |
| --- | --- | --- | --- | --- |
| TC-01 | AC-01 | <입력·기대> | <명령 또는 확인 절차> | 미실행 |
```

고정된 작업 개수를 요구하지 않는다. 원문·목적·전체 범위를 복사하지 않는다. 기존 표의 완료·처리 내용·결과도 계속 지원한다. 완료 주장은 실행 증거가 아니며 현재 HEAD·미커밋 변경을 식별한다. 구현·결과 기록은 [task-implement](../../task-implement/SKILL.md)를 따른다.
