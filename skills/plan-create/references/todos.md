# todo 양식과 진행 규칙

plan의 단계마다 `task-{nn}-{step-title}.md` 하나를 만든다. 파일 이름 규칙은 [디렉토리 규칙](plan.md#디렉토리-규칙)을 따른다. 맥락·결정은 plan에 두고, todo에는 이 단계의 변경 대상·작업·검증만 둔다.

## todo 템플릿

```markdown
# <nn> <단계 제목>

계획: [plan의 단계 표](plan.md#단계)

## 변경 대상

| 구분 | 경로 | 이유 |
| --- | --- | --- |
| Create / Modify / Delete / Test | <경로> | <역할 또는 바꿀 동작> |

## 작업

| # | 작업 | 완료 | 처리 내용 |
| --- | --- | --- | --- |
| 1 | <관찰 가능한 결과를 만드는 작업> | [ ] | |

## 검증

| 사례 | AC | 명령·작업 디렉토리 | 기대 결과 | 결과 |
| --- | --- | --- | --- | --- |
| <a id="tc-01"></a>TC-01 | AC-01 | <명령>, <리포 상대 경로> | <기대 값·동작> | 미실행 |

## 제외 범위

- <이 단계에서 바꾸지 않는 것>
```

## 작성 규칙

| 절 | 작성 규칙 |
| --- | --- |
| 변경 대상 | 확인한 경로만 쓴다. 미확인 경로는 조사 작업의 결과로 채운다. |
| 작업 | 커밋하거나 검증할 수 있는 단위로 3~7개를 쓴다. 파일·함수 수준의 하위 task로 나누지 않는다. |
| 검증 | `AC` 열에는 Issue 달성 조건의 ID(`AC-01`)를 쓴다. 사례 ID에 `<a id="tc-nn"></a>` 앵커를 둔다. plan의 단계 표는 `task-01-<step-title>.md#tc-01` 주소로 링크한다. |
| 제외 범위 | 다른 단계가 맡는 변경과 이번에 하지 않는 변경을 쓴다. |

## 예제

```markdown
# 01 오류 분류

계획: [plan의 단계 표](plan.md#단계)

## 변경 대상

| 구분 | 경로 | 이유 |
| --- | --- | --- |
| Modify | `src/retry.ts` | 오류 종류별 재시도 여부 반환 |
| Test | `tests/retry.test.ts` | 분류 사례 assertion |

## 작업

| # | 작업 | 완료 | 처리 내용 |
| --- | --- | --- | --- |
| 1 | network·expired·unknown 오류 분류 함수 구현 | [x] | `classifyRetry` 추가, unknown은 기존 안내 반환 (a1b2c3d) |
| 2 | 사례별 유닛 테스트 작성 | [ ] | |

## 검증

| 사례 | AC | 명령·작업 디렉토리 | 기대 결과 | 결과 |
| --- | --- | --- | --- | --- |
| <a id="tc-01"></a>TC-01 | AC-01 | `npm test -- tests/retry.test.ts`, 리포 루트 | network 입력에서 true | 미실행 |
| <a id="tc-02"></a>TC-02 | AC-01 | 같은 명령 | expired 입력에서 false | 미실행 |

## 제외 범위

- 결제 요청 자동 재전송
- 안내 화면 문구 변경 (02 단계)
```

## 진행 규칙

1. plan의 단계 순서대로 작업한다.
2. 작업을 마치면 `완료`를 `[x]`로 바꾸고 `처리 내용`에 한 줄 요약과 커밋을 쓴다. 계획과 다르게 처리했으면 그 이유도 쓴다.
3. 검증을 실행하면 `결과`에 통과·실패와 실행 커밋을 쓴다. 실행하지 않은 사례는 `미실행`으로 둔다. 완료 표시는 실행 증거가 아니다.
4. 명령 출력, 환경, 시각 등 상세 실행 근거는 [구현 인계](../../pr-create/references/handoff.md)에 기록한다.
5. 소스가 바뀌면 영향받는 검증의 `결과`를 `미실행`으로 되돌린다. 이전 결과는 handoff에 해당 커밋의 이력으로 남는다.
6. 모든 작업과 검증이 끝나면 plan 단계 표의 `완료`를 체크한다.
7. 계획 이탈은 plan의 결정과 변경 기록에 남긴다. 자기 커밋 hash를 같은 커밋 파일에 넣으려고 amend를 반복하지 않는다.
