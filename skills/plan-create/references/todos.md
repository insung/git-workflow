# 단위 Todo 작성·진행 계약

작은 작업은 `todos.md`에 묶고 여러 단위는 plan 01에 `01-todos.md`, 02에 `02-todos.md`로 대응시킨다. 각 파일은 관련 plan 섹션에 연결한다. Issue 맥락·기준 커밋·담당·승인 정보는 plan에 두고 todo는 구체 작업과 검증에 집중한다.

## Todo 양식

```markdown
# 01 <단위 이름>

계획: [01 계획](plan.md#01-섹션)

## <구체 작업 제목>

- [ ] <관찰 가능한 결과를 만드는 작업>
    - [ ] <파일·함수와 변경 동작이 명시된 task 1>
    - [ ] <실패·경계 처리의 구체 task 2>
    - [ ] <AC에 대응하는 테스트와 assertion task 3>
- [ ] <검증 명령 실행 및 기대 결과 확인>
    - [ ] <프로젝트 명령, 리포 상대 실행 위치, 필요한 환경>
    - [ ] <기대 값·동작과 실제 결과 대조; 미실행이면 이유 기록>
    - [ ] <상세 테스트 결과의 handoff 링크 연결>

검증 결과: <미실행 / 통과 / 실패와 근거 링크>

## <다음 구체 작업 제목>

- [ ] <다음 결과>
    - [ ] <구체 task>
```

## 채운 예제: 일시 오류와 만료 오류 분류

가상 사례이며 실제 실행 증거가 아니다. 파일과 명령은 프로젝트에서 확인한 것으로 바꾼다.

```markdown
# 01 오류 분류

계획: [오류 분류 계획](plan.md#01-오류-분류)

## 재시도 가능한 오류 분류 함수 구현

- [ ] 오류 종류에 따른 재시도 여부 반환
    - [ ] src/retry.ts에서 network 오류를 재시도 가능으로 분류
    - [ ] expired 오류는 재시도 불가로 분류
    - [ ] 알 수 없는 오류는 기존 안내 처리로 반환
- [ ] 분류 결과를 유닛 테스트로 검증
    - [ ] tests/retry.test.ts에 network 입력의 true assertion 추가 (TC-01 / AC-01)
    - [ ] expired 입력의 false assertion 추가 (TC-02 / AC-01)
    - [ ] unknown 입력에서 기존 안내 유지 assertion 추가 (TC-03)
    - [ ] 확인한 unit 명령 실행 후 세 사례의 기대/실제 결과 비교
    - [ ] handoff.md에 실행 명령·위치·revision·환경·시각·결과 기록

검증 결과: 미실행; 구현 후 handoff.md의 테스트 결과에 연결
```

## 진행과 완료 의미

구현 담당은 plan의 선행 조건을 확인하고 todo 순서로 작업한다. 구현 task와 검증 task는 각각 실제 수행한 경우에만 체크한다. 체크박스 자체는 테스트 실행 증거가 아니다. 상세 사례별 기대/실제·명령과 작업 디렉토리·revision/dirty identity·환경·시각은 [구현 인계](../../pr-create/references/handoff.md)에 기록하며 todo에는 해당 결과 링크를 연결한다.

다른 세션이나 최종 단계에서 검증하기로 했다면 검증 task를 미체크·미실행으로 유지하고 plan의 검증 시점에 연결한다. 소스가 바뀌면 영향받는 검증 task를 다시 열고 이전 결과는 해당 revision의 이력으로 유지한다. 최종 통합 검증이 남으면 전체 완료가 아니다.

커밋 결과와 계획 이탈은 handoff와 plan에 기록한다. 자기 hash를 같은 커밋의 파일에 넣기 위해 amend를 반복하지 않는다. 최종 코드 revision과 이후 문서 전용 변경을 구분한다.
