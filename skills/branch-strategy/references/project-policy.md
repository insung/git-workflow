# 프로젝트 브랜치 정책 읽기

브랜치 생성·PR 대상 결정·hotfix 분기와 반영 전에 읽는다. 스킬 이름이 없는 일반 요청에도 같은 순서를 적용한다. 전략은 프로젝트 문서가 정본이며 이 참조는 찾기·적용 절차만 정의한다.

1. 대상 프로젝트와 적용되는 루트·하위 `AGENTS.md`를 읽고 브랜치 정책의 경로와 적용 범위를 확인한다.
2. 연결된 정본(기존 정책 문서, `BRANCH-STRATEGY.md`, README의 지정 절 또는 AGENTS의 간단 정책)을 읽는다. 연결이 없으면 프로젝트의 해당 문서·기여 안내에서 명시된 정책을 찾는다. 전략 문서의 존재만으로 승인된 정책이나 자동 읽기를 주장하지 않는다.
3. 적용되는 정책의 base·작업 이름·PR 대상·hotfix 기준과 첫 반영·역반영 경로를 현재 요청과 대조한다. 승인된 프로젝트 정책이 이 패키지의 dev/prod 예시보다 우선이다. 사용자 요청과 정책이 충돌하면 현재 사용자의 명시적 예외 승인 범위를 확인하고, 없다면 충돌과 필요한 결정만 질문한다.
4. 문서끼리 충돌하거나 필요한 규칙이 미정이면 그 규칙이 필요한 행동만 보류한다. 이력으로 정책을 확정하거나 브랜치 이름으로 배포 커밋을 추정하지 않는다. 무관한 조사까지 보류하지 않는다.
5. 정책이 없으면 요청에 명시된 base·이름으로 범위 내 작업을 처리할 수 있다. 부족한 결정만 확인하며 dev/prod를 자동 적용하거나 전략 초기화를 강제하지 않는다. 지속적인 전략 기록을 원하면 [workflow-init](../../workflow-init/SKILL.md)의 브랜치 전략 항목으로 연결한다.

정본 경로/절·사용한 규칙·현재 base 커밋·남은 결정과 실제 실행을 구분한다. 파일을 찾고 읽었다는 증거와 실제 정책 준수를 구별한다. README와 BRANCH-STRATEGY.md는 모든 AI 호스트에서 자동 로드되는 파일이 아니므로, 지속적인 읽기는 적용되는 AI 지침과 실행 시나리오로 확인한다.
