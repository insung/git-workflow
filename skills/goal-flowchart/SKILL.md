# Goal Flowchart

관리 세션의 사용자는 여러 하위 세션의 보고를 한눈에 보고 「이대로 목표에 닿는가, 무엇이 막고 있는가」를 판단하고 싶어 한다. 그래서 답은 **판정 한 문단 + 순서도 하나 + 남은 일의 순서**다. 순서도는 판정의 근거이고, 판정 없는 순서도는 사용자가 결론을 스스로 찾게 만든다.

## 1. 근거 모으기 (보고를 그대로 믿지 않는다)

하위 세션 보고는 그 세션의 주장이다. 상자에 「완료」를 쓰기 전에 원본 데이터로 다시 확인한다.

- Issue·PR 로 추적하는 작업은 대상 저장소마다 열린 Issue·PR, 머지된 PR, 기본 브랜치 HEAD 를 조회한다(예: `gh issue list --state open`, `gh pr list --state merged`, `git log -1`). 저장소별 gh 계정 규칙이 있으면 따른다.
- Issue·PR 이 없는 작업은 결과 파일과 커밋을 직접 확인해 완료를 정한다. 이 스킬은 보고만 하므로 Issue 생성이나 Issue 필요 판정을 요구하지 않는다.
- 보고에 적힌 PR·Issue 번호가 실제로 MERGED·CLOSED 인지 확인한다. 다르면 상자에 실제 상태를 쓰고 답에서 짚는다.
- Issue 본문의 「다음 행동」「차단 요인」(이전 템플릿은 「막힌 것」) 줄을 읽어, 보고에 없던 남은 일과 오래된 기록을 찾는다.
- 보고끼리 어긋나거나, 보고를 옮긴 앞선 내 답이 틀렸으면 정정 항목으로 남긴다.

## 2. 목표 달성 판정

세션 목표를 한 문장으로 다시 적고, 다음 중 하나로 판정한다.

- **달성** — 목표의 완료 조건이 모두 원본 데이터로 확인됨.
- **달성 가능** — 남은 일이 있지만 막는 결정·외부 의존이 없음.
- **조건부** — 남은 일 중 사용자 결정이나 외부 의존이 목표를 막음. 무엇이 막는지 이름을 댄다.
- **현재 범위로는 불가** — 목표의 전제가 바뀌었거나(예: 방향 변경 요청) 빠진 구성 요소가 있음.

목표에 단계(예: 구현 단계와 운영 단계)가 섞여 있으면 단계마다 따로 판정한다. 한 판정으로 뭉치면 「다 됐다」와 「아직 멀었다」가 동시에 참인 상황을 숨긴다.

## 3. 순서도

작업마다 **상자 하나**. 상자를 단계(입력 → 처리 → 저장 → 운영처럼 실제 흐름 순서)로 묶는다. 시각화 도구(show_widget 등)가 있으면 HTML 로 그리고, 없으면 Markdown 으로 같은 구조를 쓴다.

순서도는 세션을 읽지 않은 사람이 그림만 보고 이해할 수 있어야 한다. 사용자가 「(다)가 무엇인지, 노트 8절 기록이 무엇을 위한 일인지 알 수 없다」고 느끼는 것이 막으려는 실패다.

### 최종 목표 줄

순서도 맨 아래, 마지막 단계 뒤에 「최종 목표」 줄을 둔다. 모든 단계가 이 줄로 모이게 그리고, 테두리는 단계 영역보다 굵게 한다.

- 내용: 결과물과 그 결과물을 누가 어디에 쓰는지만 쓰고, 이름표에 2절의 판정을 붙인다. 된 것과 남은 조건은 위 상자들의 status 와 답의 「차단 요인」이 보여 주므로 이 줄에 다시 쓰지 않는다.
- 사용자가 직접 말하지 않은 목표는 「최종 목표 (예상)」으로 쓰고, 답에서 맞는지 확인을 받는다.
- 단계 머리에 「쓰이는 곳」을 반복하지 않는다. 단계가 결국 어디에 쓰이는지는 이 줄이 보여 준다.

### 단계와 화살표

단계 사이의 화살표와 단계 안의 화살표는 모양이 달라야 한다. 비슷하면 사용자가 「다음 단계로 넘어감」과 「같은 단계 안의 다음 작업」을 구별하지 못한다.

- **단계:** 점선 테두리 영역 하나로 묶는다. 영역 머리에 「N단계 · 이름 (이 단계에서 알아내거나 만드는 것)」을 쓴다. 예: 「2단계 · 항목별 판정 (항목마다 지금 batch 로 되는지, 새로 만들지 여부 파악)」. 괄호 안은 한 구로 짧게 쓰고 화살표나 칸 이름을 넣지 않는다.
- **단계 사이:** 영역 밖에 굵은 세로 막대와 「▼」를 둔다. 범위나 방향이 바뀐 이유(예: 「사용자 지적: …」)가 있으면 이 화살표 아래에 한 줄로 쓴다.
- **단계 안:** 실행한 순서대로 상자 사이에 작은 회색 「›」를 둔다.
- **서로 의존하지 않는 작업:** 화살표 없이 나란히 두고, 단계 이름에 「서로 독립」을 쓴다.

### 상자 내용

상자에 고정된 칸은 없다. 이름표(status)와 작업 이름만 필수이고, 나머지는 그 작업을 판단하는 데 필요한 내용만 짧게 쓴다(무엇을 했는지, 결정이 바뀐 내용, 커밋·PR 번호, 남은 조건 등). 칸 이름을 쓰는 경우에는 「목표: …」처럼 이름 뒤에 콜론을 붙여 내용과 구분한다.

**작업 이름에는 그 작업이 이루려는 것을 쓴다.** 수단(기록, 조회, 호출 등)은 이름 뒤 괄호나 설명으로 옮긴다. 목적 칸을 따로 두지 않아도 이름만 보고 무엇을 위한 일인지 알 수 있게 하려는 것이다.

| 수단만 적은 이름 | 목적을 적은 이름 |
| --- | --- |
| 노트 8절 기록 | 음성·카카오톡 제외 결정을 관리 세션에 넘기기 (공유 노트에 기록) |
| 2. 매일 → 주간 발행 | 리포트를 주 1회 발행으로 바꿀 수 있는지 판정 |

**약어와 번호를 단독으로 쓰지 않는다.** 판정 기호(「(가)」~「(라)」), 결정 번호(「d1」), 문서 절 번호(「8절」), 요청 항목 번호(「1번」)처럼 그 세션 안에서만 통하는 표시는 뜻을 먼저 풀어 쓴다. 추적에 번호가 필요하면 뜻 뒤 괄호에 붙인다. 예: 「(다) 큰 작업」 → 「지금 흐름에 없어 새로 만들어야 하는 큰 작업」.

**그리기 전에 점검한다.** 세션을 읽지 않은 사람이 상자 이름만 보고 무엇을 위해 하는 일인지 알 수 있는지 상자마다 확인하고, 알 수 없으면 이름을 다시 쓴다.

Issue·PR 번호는 작업 묶음 기준으로 한 번만 쓴다.

- 한 단계의 작업이 모두 같은 Issue 이면 영역 머리에 「Issue #99 · PR #100」처럼 한 번 쓰고 상자마다 반복하지 않는다.
- 한 단계에 Issue 가 다른 작업이 섞여 있으면 해당 상자에만 번호를 쓴다. 다른 저장소면 `저장소#번호` 로 쓴다.
- Issue 가 없는 작업이나 단계에는 번호를 쓰지 않는다(「없음」이라고 쓰지 않는다).

저장소가 여럿이면 주 저장소와 다른 저장소를 구분해 보이게 한다(단계 이름이나 `저장소#번호`).

### status

상자마다 아래 값 중 하나를 이름표로 붙이고, 같은 색으로 테두리를 칠한다. 순서도 맨 위에 다섯 값의 범례를 둔다. 최종 목표 줄에는 status 대신 2절의 판정을 이름표로 붙인다.

| status | 뜻 | 색 |
| --- | --- | --- |
| `done` | 원본 데이터(GitHub·파일·커밋)에서 확인된 완료 | 초록 |
| `now` | 하위 세션이 작업 중 | 파랑 |
| `wait_user` | 사용자 승인·결정·실행 대기 | 주황 |
| `todo` | 선행 작업이 끝나지 않아 시작 전 | 회색 테두리 |
| `dropped` | 하지 않기로 함 | 점선 테두리, 흐리게, 이름표에 취소선 |

1절에서 원본 데이터로 확인하지 못한 완료는 `done` 으로 칠하지 않는다. 상자 설명에 「보고상 완료, 미확인」을 쓰고, 확인할 때까지 보고 전 status(대개 `now`)를 유지한다. 완료 상자가 많아도 접지 않는다 — 사용자가 「무엇을 완료했는지 알 수 없다」고 느끼는 것이 이 스킬이 막으려는 실패다.

## 4. 답의 구성 (순서도 밖의 글)

1. 첫 줄: 판정 한 문장.
2. **달성한 것** — 목표 기준으로 2~4줄. 순서도 내용을 다시 나열하지 않는다.
3. **차단 요인** — 목표를 막는 `wait_user`·`todo` 상자마다 왜 막는지, 무엇이 정해져야 풀리는지.
4. **정정** — 1절에서 찾은 보고와 실제의 차이, 내 앞선 답의 오류. 없으면 뺀다.
5. **권장 순서** — 남은 일을 의존 관계대로 번호 매겨. 결정 없이 지금 할 수 있는 일을 먼저 둔다.
6. 사용자 승인이 필요한 다음 한 걸음이 있으면 질문 하나로 묻는다.

## 하지 않는 것

- 관리 세션 규칙이 있으면 재검토 중에 발견한 일을 직접 고치지 않는다. 고칠 일은 권장 순서에 넣고, 진행은 사용자 결정이나 하위 세션 지시로 넘긴다.
- 확인하지 못한 완료를 `done` 으로 칠하지 않는다. 확인하지 못했으면 상자 설명에 「보고상 완료, 미확인」이라고 쓴다.
