# 구현과 PR 리뷰 인계 계약

대상 작업 디렉토리 handoff.md에 기록한다. plan/todo를 복사하지 않고 실제 완료와 이탈·미확인만 정리한다. 승인된 범위에서 Issue/PR에는 요약과 이 문서의 확인된 링크를 남긴다.

```markdown
# 구현과 PR 리뷰 인계

- Issue / PR: <실제 URL 또는 초안 상태>
- Plan / Todo: <원본 상대 링크와 현재 상태>
- base / 구현 코드 commit / 검토 HEAD / 미커밋 변경 파일·patch/digest / 확인 시각:
- 실제 실행 담당과 검토 방식: <현재 또는 별도 세션; 미확인 ID를 만들지 않음>
- spec-it manifest/lock·policy pin·정본 위치/접근 상태:

## 사용자 의도와 구현 결과

| AC | 기대 동작 | 구현 경로/commit | 대응 todo/TC | 실제 충족·미확인 |
| --- | --- | --- | --- | --- |

## 계획 대비 차이와 판단

- 변경 범위·미변경 소비자 영향·선택 이유·제외 범위
- todo에 없던 파일/동작과 이유, 추가 결정·승인 상태

## 검증 요약과 증거

| TC/AC | 사례와 테스트 파일 | 기대 | 실제·상태 | 명령·실행 위치 | 커밋·환경·시각 |
| --- | --- | --- | --- | --- | --- |
| <TC-01 / AC-01> | <관찰 입력·대응 assertion> | <기대 값/동작> | <실제 값과 pass/fail/not-run> | <실제로 실행한 명령/cwd> | <확인한 실행 근거> |

- 의미 있는 unit test와 정상·실패·경계·유지 사례:
- 실제 명령·cwd·실행 커밋과 미커밋 변경 근거·환경·시각과 결과 위치:
- 최종 통합/회귀 여부, 미실행·누락·제외 이유와 대체 검사:

## 커밋과 문서 상태

- 코드 commit·관련 문서-only 후속 commit·미커밋 변경:
- 확인된 원격 docs 링크와 아직 로컬인 문서:

## 위험·배포·롤백

- plan의 전달/배포 조건·미확인 환경·필요 승인·검토할 위험:

## 다음 검토

- 고정 base/HEAD·재현할 명령·필요한 사람 결정/추가 증거:
```

예: AC-01의 분류 함수는 구현했고 TC-01/02를 실행했지만 실제 사용자 환경 통합 검증은 not-run이라면 그 차이를 명시한다. unit test pass로 배포 준비 완료를 주장하지 않는다.
